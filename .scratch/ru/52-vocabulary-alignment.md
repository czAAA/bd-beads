# 52: Привести имена в коде в соответствие с глоссарием

**Что сделать:** имена в проекте совпадают с его собственным языком. Тот, кто ищет Количество бисера, находит модуль, названный именно так; у набора сохранённых Схем появляется имя в CONTEXT.md; ничего не экспортируется, если это никем не вызывается.

- **В CONTEXT.md добавляется статья «Библиотека схем».** Набор всех Схем, сохранённых на этом устройстве, встречается по всей системе — его перечисляет блок «Сохранённые схемы», его целиком выгружает файл схемы в режиме библиотеки, и сама статья про файл схемы уже говорит «одну Схему или всю библиотеку», — но определения у него никогда не было. Согласованная формулировка:

  > **Pattern library** (RU: Библиотека схем):
  > Все Схемы, сохранённые на этом устройстве, взятые вместе — то, что перечисляет блок «Сохранённые схемы» и что целиком выгружается одним файлом схемы. Это плоский набор без порядка, группировки и вложенности: Схема попадает в библиотеку в момент создания и покидает её только при удалении. Существует только на том устройстве, где была создана (ADR 0001), поэтому перенести её куда-либо можно лишь через файл схемы.
  > _Избегать_: коллекция, галерея, список сохранённого, рабочее пространство

- **`beadMapping.ts` переименовывается в `beadQuantities.ts`.** Модуль считает Количество бисера — это термин глоссария, — а назван по сопоставлению цвета и бисера, от которого отказались в ADR 0007.
- **`beadStorage.ts` переносится в `beads.ts`.** Он ничего не хранит: это один поиск по константному каталогу. Его тесты объединяются с тестами каталога.
- **Удаляются два мёртвых экспорта домена вместе с их тестами:** вставка блока без Отражения (заменена версией с Отражением в тикете 50) и закраска одной ячейки (заменена многоячеечной в тикете 24). Ни у того, ни у другого нет вызовов вне собственного теста.
- **Удаляется неиспользуемый ключ `shell.mainPanelPlaceholder`** из интерфейса переводов и из обоих словарей.
- **Удаляется `@testing-library/jest-dom`.** Файл `setupTests.ts` состоит из одного импорта, который подключает примерно 30 дополнительных матчеров, и ни один из них нигде не используется — все 663 теста проверяют результат средствами самого Vitest. Зависимость, сам `setupTests.ts` и запись `setupFiles` в конфиге Vite удаляются вместе.
- **Исправляется `docs/agents/issue-tracker.md`:** он должен описывать плоскую схему `.scratch/NN-slug.md`, которая реально используется, а не раскладку по папкам на каждую задачу, от которой практика давно отошла.

Поведение не меняется: тот же интерфейс, те же сохранённые данные, те же выгружаемые файлы.

**Блокируется:** ничем (можно начинать сразу)

**Статус:** ready-for-agent

**Решения (2026-09-17):**
- «Библиотека схем», а не просто «Библиотека»: одно слово «библиотека» слишком общее рядом с «файлом схемы» и «каталогом бисера» в том же глоссарии, а формат выгрузки уже использует `bd-beads/library` внутри вида, привязанного к Схеме.
- Статья фиксирует библиотеку как плоский набор без порядка, группировки и вложенности. Это и есть самая ценная её часть: будущий вопрос «а можно ли раскладывать Схемы по папкам?» должен находить текущий ответ записанным. Если ответ изменится, поправить одну строку глоссария — самое дешёвое изменение из возможных.
- Тикет идёт первым, чтобы тикеты 55 и 56 писались в правильной терминологии с первой строки, а не переименовывались потом.
- Только переименования и удаления. Ни один модуль не разделяется и не перестраивается, кроме переноса однофункционального поиска в сам каталог.
- Удаление jest-dom проверено на практике, а не выведено из рассуждений: весь набор тестов был один раз запущен вообще без `setupFiles` и прошёл без изменений — 30 файлов, 663 теста. Ничто в репозитории не зависит от матчеров, которые он подключает.
