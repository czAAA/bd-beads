# 61: Предупреждать по Технике плетения, если кадрирование рискует тормозить

**Что сделать:** В форме создания новой Схемы, рядом с полем выбора файла для Конвертировать изображение, показывается ненавязчивая информационная подсказка, когда уже выбранные Бисер + Техника плетения + размер дадут количество ячеек, слишком большое для плавного предпросмотра кадрирования. Подсказка обновляется вживую при изменении Бисера, Техники плетения, ширины, высоты или единиц измерения — тех же полей, что форма уже отслеживает для своего события `draft`, — и появляется ещё до выбора файла, чтобы стоимость была известна заранее.

Кадрирование (тикет 58, ADR 0010) рисует один позиционированный DOM-элемент на бисерину и на каждое перемещение курсора при перетаскивании пересэмплирует всю решётку целиком; `PREVIEW_MAX_CELLS` (сейчас 12 000, см. [imageFraming.ts](../../src/domain/imageFraming.ts)) — это бюджет, подобранный именно для плавности, и он ограничивает только *окружающий* контекст — сама рамка рисуется всегда целиком. Схема 300×300мм на любой бисерине из каталога уже превышает этот бюджет одной только рамкой (Delica: ~43 400 ячеек; TOHO Cube: 40 000; TOHO Round: ~18 500) — именно этот случай подсказка и должна упредить.

У каждой Техники плетения — своё сообщение и своя пороговая константа, чтобы их можно было настраивать по отдельности в дальнейшем, но данных профилирования, показывающих, что одна Техника плетения реально тормозит при другом количестве ячеек, чем другая, сегодня нет — стоимость отрисовки зависит от количества ячеек, а не от смещения рядов или их плотности. **Решение:** все три техники стартуют с одного и того же числа, `PREVIEW_MAX_CELLS` (12 000), как отправной точки; три константы не объединяются в одну, чтобы будущий тикет мог сдвинуть только одну из них, когда кто-то реально почувствует, что одна Техника плетения тормозит раньше другой.

Намеренно **вне** объёма: изменение самого `PREVIEW_MAX_CELLS` или того, как рисуется предпросмотр кадрирования (виртуализация, поднятие потолка) — этот тикет только добавляет более раннее информационное предупреждение, используя уже существующий бюджет как есть.

**Критерии приёмки:**
- [ ] Существуют три независимо именованные пороговые константы по количеству ячеек (loom / peyote / brick), все стартуют со значения `PREVIEW_MAX_CELLS`
- [ ] Форма создания новой Схемы показывает локализованную (на английском и русском) подсказку в поле Конвертировать изображение, как только текущие Бисер + Техника плетения + размер дают решётку (`computeGridDimensions`) с количеством ячеек ≥ порога для этой Техники плетения, и скрывает её иначе
- [ ] Текст подсказки называет Технику плетения и сообщает, что кадрирование при таком размере может тормозить — это обычная подсказка, а не оформление в виде ошибки поля
- [ ] Подсказка обновляется вживую при изменении любого из полей: Бисер, Техника плетения, ширина, высота, единицы измерения — без необходимости повторно отправлять форму или сначала выбирать файл
- [ ] Подсказка никогда не отключает поле выбора файла и не блокирует конвертацию — она исключительно информационная
- [ ] Модульные тесты покрывают: чуть ниже порога (скрыта), на пороге (показана), чуть выше (показана), а также переключение только Техники плетения при неизменном физическом размере и Бисере включает/выключает подсказку

**Блокируется:** ничем (можно начинать сразу)

**Статус:** ready-for-agent
