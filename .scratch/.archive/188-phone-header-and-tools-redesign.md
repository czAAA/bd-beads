**Done (ticket 188):** Traced the reported symptoms (Redo cut off, the More button "missing", the zoom pill "off") to their actual causes with a real browser (Playwright) rather than guessing from the CSS alone, since several of them turned out to share one root cause:

- **The header genuinely overflowed 390px.** `.app-header__phone-pattern` (the old Pattern name/size/save-state block) measured ~230px wide on its own; combined with everything else, the header's `scrollWidth` was 566px against a 390px `clientWidth`, `overflow: hidden` silently clipping Redo and the whole More button off-screen. Moving the Pattern-name block into the More menu (as a phone-only row, same pattern as the menu's other rows) reclaimed most of that; tightening the header's gap to 4px at the phone tier closed the rest.
- **A second, independent overflow bug**: `.app-header__phone-hide`/`.app-header__wide-only` (the generic "hide below 1024px" utility classes) were losing the CSS cascade to some elements' own later-defined `display: flex` rule at equal specificity — `.app-header__editing` ("currently editing") was leaking a few invisible-but-still-laid-out px into the header even though it correctly showed `display: none` semantically. Made the utility rule `!important`, since a "hide this" utility has to always win over whatever else touches `display` on the same element.
- **The zoom pill wasn't "off-center", it wasn't floating at all.** `.app-shell__drawing > :not(.canvas-backdrop) { position: relative }` (a rule giving every layer above the canvas background its own stacking context) outranks `.app-shell__zoom-pill`'s own `position: absolute` by specificity (three class-equivalent selectors vs. two), so the pill stayed in normal flow, stretching across the top of the canvas box as a block instead of floating over its bottom-right corner. Excluded `.app-shell__zoom-pill` from the broad rule; its icons were centered all along; only its position was broken.
- **The Size sheet's info tooltip auto-opened** because `BottomSheet`/`AppDrawer` focus the first focusable element in their body on open, and that first element happened to be `SizeControls`' info button, whose `@focus` handler (correctly) opens the tooltip for keyboard users. Added `data-skip-autofocus`, an opt-out `BottomSheet`/`AppDrawer` skip only when picking *where opening focus lands* — the control stays reachable by Tab exactly as before.
- **Three new Icons v2 icons**, added to the design system on claude.ai first (per DESIGN.md §6) then synced in: `bead` (a rounded bead module with its drilled hole — the app's own compact-header mark) and `library` (three shelved spines — Saved Patterns, replacing its former reuse of the unrelated `save` icon, at every tier via a new optional `icon` prop on `ExpandablePanel`) were the ticket's own ask; `paste` (a clipboard with two lines) was added after finding the actual "Import in the Edit group" complaint was the phone Edit sheet's Paste button visually reusing the `import` icon glyph, not any real Import feature sitting in Edit.
- **Progress bar compact mode**: `ProgressBar.vue` gained phone-only siblings of its existing controls (a "1/222" `<p>`, icon-only `IconButton`s for Row not done/Row done) toggled by the same `phone-only`/`phone-hide` CSS pattern the header already used, rather than a prop-driven variant — kept the desktop markup and its testids untouched.
- Code review (Standards + Spec sub-agents, two-axis) caught one real issue: the phone header's new technique/schema selector originally reused the `grid` icon, which the Iconography section already assigns to the canvas strip's zoom cluster — an undocumented, unrelated reuse. Swapped to `size` (already the Size row's icon, and both surface the same Bead), and documented the reuse in the design system.

Verified in a real browser (Playwright/Chromium, 390×844) at each step — screenshotted the header, the zoom pill, the compact Progress bar, the More menu's new Pattern-name row, the Pattern sheet opened from the bead/technique icon, and the theme sheet — rather than trusting jsdom, which doesn't evaluate `@media` or compute real layout.
