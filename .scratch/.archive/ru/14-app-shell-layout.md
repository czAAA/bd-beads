# 14: Перестроить каркас приложения в layout инструментального приложения

**Что нужно сделать:** Реорганизовать текущий layout приложения в каркас инструментального приложения — верхняя панель плюс основная панель, панель над холстом, холст и панель под холстом — по духу приложенного скриншота-референса (обычное приложение для рисования). Заимствовать у референса только *структуру*, а не набор функций: у bd-beads другой, более узкий функциональный охват, и новый layout должен показывать ровно этот охват и ничего лишнего.

Заменено на [ADR 0004](../../../../docs/adr/0004-three-panel-app-shell.md) — это авторитетное описание итоговой структуры панелей и правил размещения; layout этого тикета был перестроен в четырёхпанельную модель после того, как тикету 16 потребовался собственный холст в рамках экрана.

**Целевой layout (только функции bd-beads):**
- **Верхняя панель:** название приложения, индикатор текущей схемы (название/сводка, тикет 05), переключатель языка (тикет 03)
- **Основная панель:** форма новой схемы; выбор цвета из палитры и инструмент рисования (тикет 07), заливка (тикет 08), переключатели осей зеркала (тикет 09), отмена/повтор (тикет 07), настройки техники/размера холста (тикеты 01, 06), очистка/сброс присоединяются по мере готовности тикетов
- **Над холстом:** всегда видимые действия (новая схема)
- **Холст:** сетка/холст схемы в собственном контейнере фиксированного размера (тикет 16)
- **Под холстом:** список сохранённых схем/переключатель (тикет 05); переключатель прогресса по рядам (тикет 13), каталог бисера и сводка по количеству бисера на цвет (тикеты 10, 11), действия экспорта/импорта (тикет 12) присоединяются по мере готовности тикетов

**Явно вне рамок задачи** (есть на скриншоте-референсе, но не относится к bd-beads): логин/регистрация, галерея, "Animate", загрузка/библиотека/объекты изображений, обобщённая панель слоёв, управление клонированием/отражением объектов, тенью, прозрачностью.

**Блокируется:** 01, 02

**Статус:** done

- [ ] Каркас приложения рендерится как верхняя панель плюс четыре панели по структуре ADR 0004: основная панель, панель над холстом, холст, панель под холстом
- [ ] Каждый элемент управления в новом layout соответствует существующей или запланированной функции bd-beads согласно целевому layout выше; ни одна из явно исключённых функций референса не добавляется
- [ ] Весь уже работающий функционал (рисование схемы, переключение схем, i18n и т.д.) продолжает работать после переноса — это реорганизация существующего/запланированного интерфейса, а не разработка новых функций
- [ ] Если функция ещё не реализована в своём тикете, для неё просто нет элемента управления в каркасе — без заглушек/placeholder'ов
- [ ] Layout использует дизайн-токены из тикета 02, а не разовые стили
