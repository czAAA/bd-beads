# 49: Копирование снимает выделение

**Что нужно сделать:** После копирования выделенная область сразу пропадает — так же, как если бы был клик правой кнопкой или Escape при пустом буфере обмена. Буфер обмена остаётся заряжен, следующий клик по-прежнему вставляет скопированное. Чтобы скопировать тот же блок ещё раз, нужно заново выделить его — подсвеченной области для повторного копирования больше нет.

**Блокируется:** Ничем (можно начинать сразу)

**Статус:** ready-for-agent

**Решения (2026-09-17):**
- Термины глоссария: **Выделение** и **Копировать** — см. CONTEXT.md (уже обновлено).
- Снимается только выделение; буфер обмена (`copiedBlock`) не затрагивается.
- Это отменяет прежнее намеренное поведение, при котором выделение оставалось подсвеченным после копирования специально для того, чтобы можно было скопировать тот же блок повторно без нового выделения — этим удобством сознательно жертвуют ради выделения, которое не задерживается после использования.
- Клик правой кнопкой / Escape в остальном не меняются: при заряженном буфере они по-прежнему отменяют ожидающую вставку (сохранять выделение уже незачем — оно снято ещё при копировании); при пустом буфере они по-прежнему снимают активное выделение.

- [ ] Клик по «Копировать» сразу скрывает подсветку выделенной области
- [ ] Буфер обмена по-прежнему хранит скопированный блок; следующий клик вставляет его как обычно
- [ ] Чтобы скопировать тот же блок снова, нужно сначала выделить его заново
- [ ] Клик правой кнопкой / Escape при заряженном буфере по-прежнему отменяют ожидающую вставку, как раньше
- [ ] Клик правой кнопкой / Escape при пустом буфере по-прежнему снимают активное выделение, как раньше
