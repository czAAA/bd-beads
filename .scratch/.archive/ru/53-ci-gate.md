# 53: Запускать тесты, типы и линтер в CI

**Что сделать:** красные тесты или ошибка типов больше не могут незаметно попасть в main или на GitHub Pages.

Сейчас единственная автоматизация — workflow деплоя на Pages, который на каждый push в main выполняет `npm ci && npm run build`. Внутри сборки работает `vue-tsc -b`, так что ошибки типов задеплоиться не могут, — но 663 теста не запускаются нигде автоматически, а на pull request не запускается вообще ничего, хотя именно туда и приходит вся работа.

- **Workflow CI** на `push` и `pull_request`: установка, проверка типов, тесты, линтер.
- **В workflow деплоя добавляется шаг с тестами** перед сборкой, чтобы упавший прогон блокировал деплой, даже если что-то попало в main иным путём.
- **Добавляется ESLint** с набором essential из `eslint-plugin-vue` и рекомендованным набором `@typescript-eslint`, без стилистических правил. Он выполняется в CI и роняет сборку на любом предупреждении.

**Блокируется:** ничем (можно начинать сразу)

**Статус:** ready-for-agent

**Решения (2026-09-17):**
- И workflow на pull request, и проверка в деплое — не одно вместо другого. Работа мержится через PR, поэтому основная польза именно там; проверка в деплое — это две лишние строки, которые закрывают случай, когда что-то попало в main другим путём.
- ESLint без Prettier. Текущий стиль кода и так единообразен, а внедрение Prettier на ~14 тысячах строк означает один огромный коммит переформатирования, который портит `git blame` ради очень малой выгоды. Если расхождения в форматировании когда-нибудь станут заметны, Prettier можно добавить позже на куда меньшем диффе.
- Блокирующий с первого дня, но на намеренно минимальном наборе правил, а не предупреждающий на большом. Предупреждающий линтер — это линтер, который никто не читает: через две недели счётчик предупреждений превращается в шум. У минимального набора почти нет накопленного долга, поэтому проверка работает по-настоящему с первого коммита.
- Стилистический слой — это ровно тот самый объём переформатирования, от которого уже отказались вместе с Prettier. Новые правила добавляются позже и осознанно: когда правило поймало бы реально случившуюся ошибку.
- В tsconfig уже включены `noUnusedLocals`, `noUnusedParameters` и `noFallthroughCasesInSwitch`, то есть самые ценные проверки фактически уже работают; ESLint добавляет здесь прежде всего корректность, специфичную для Vue.

- [ ] Workflow CI запускает проверку типов, тесты и линтер на push и на pull request
- [ ] Деплой на Pages запускает тесты перед сборкой, и упавший прогон блокирует деплой
- [ ] ESLint настроен на essential-правила Vue плюс рекомендованный набор TypeScript, без стилистических правил
- [ ] Есть скрипт `npm run lint`, он возвращает ненулевой код на любом предупреждении и проходит на чистом чекауте
- [ ] Prettier не добавляется, и в диффе тикета нет массового переформатирования
