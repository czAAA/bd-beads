**Done (ticket 168):** the header gained a Tools button (`IconButton`, icon-only, shown 744-1023px) that opens `AppDrawer.vue` -- a new component wrapping the *same* left-column instances (Toolbox, save box, Beads needed, Saved Patterns) every tier uses, so none of their own state (an expanded panel, a roving tab stop) is duplicated across two copies. `AppDrawer` is always mounted: `display: contents` at 1024px and up leaves it invisible to the grid (an ordinary docked sidebar, ticket 167's own layout unchanged), and only `@media (min-width: 744px) and (max-width: 1023px)` turns it into a fixed, scrimmed, `transform`-sliding overlay. Its dialog behavior (the Tab focus trap, Escape via the existing `useEscapeLayer` stack -- so `hasOpenLayer()` already withholds the app's single-key shortcuts while it's open, for free -- `role="dialog"`, `inert` while closed) is gated on a *real* tier check (`useMediaQuery`, new: a small `matchMedia`-backed composable, `src/testUtils/fakeMatchMedia.ts` to fake it in tests, a `testSetup.ts` default stub since jsdom has no `matchMedia` at all) rather than trusting that `open` only ever becomes true from a button CSS already hides outside that range -- so a window resized wide while the drawer happens to be open falls back cleanly to a plain sidebar instead of leaving a stale focus trap.

`BottomToolbar.vue` (new): the four tools, Undo, Redo, and a Colour button that opens a `PalettePicker` popover of its own (anchored, `useAnchoredPosition` auto-flips it above the button since it sits at the very screen bottom) -- Custom and Image colors stay Drawer-only, a scoped simplification. A flex sibling of `.app-shell__body`, not nested in the canvas box, so it takes its own height off the screen's bottom (the same reason toasts anchored to the canvas box's own bottom edge end up above it for free, with no extra positioning math).

The More menu (`AppMenu`, reused) holds Import a file/Import QR code (a second `PatternImport` instance -- fixed a latent bug finding it: its file input `id`s were hardcoded, which two live instances would have collided on; now `useId()`), Language and Theme (the actual `LanguageSwitcher`/`ThemeToggle` widgets embedded as extra rows, since both are self-contained and already read/write global state directly), and Name on exports (the same footer-row pattern the Export ▾ menu already used). `PatternImport` gained `toastResults` (an `import-result` event instead of its own inline result -- there's no room beside two buttons in a menu) and `testidPrefix`, both new, opt-in props; the header's own instance is unaffected.

`ContextBar.vue` (new): what a Selection can do, floating 10px from the canvas box's edges above the Progress bar, wired to the exact same handlers the Toolbox's own Remove line/Copy/Rotate links and `backOutOfSelect` use -- no new domain logic, just another way to reach it. `useSelectionGesture` now also exposes `pasteProjectionActive` (previously internal), which both the "which state is this" check and the after-Copy "Tap where to paste" view need.

Known simplifications, not full parity with the cards: the More menu's arrow-key roving only reaches its `AppMenuItem`s, not the embedded PatternImport/LanguageSwitcher/ThemeToggle rows (Tab still closes the menu from anywhere inside it, as it always did); below 744px the More menu still shows with the iPad mini tier's own content (Import, Language, Theme, Name on exports) rather than the phone tier's (Theme, Language, Name on exports, Keyboard shortcuts, no imports) -- ticket 79's to fix, not built yet.

New tests: `AppDrawer.test.ts`, `BottomToolbar.test.ts`, `ContextBar.test.ts`, `useMediaQuery.test.ts`, `App.iPadMini.test.ts` (the header/Drawer/BottomToolbar/More menu/ContextBar wiring together, stubbing `matchMedia` to the drawer tier). `npm run typecheck`, `vitest run` (1885 tests) and `npm run lint` are clean.
