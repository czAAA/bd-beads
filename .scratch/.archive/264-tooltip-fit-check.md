# 264: Visual check that no Tooltip is ever cut off

**What to build:** An exhaustive check, not a sample, in the visual suite: it opens every Tooltip the app has (the hover/focus/long-press ones on icon buttons, Toolbox buttons, the zoom pill, the header and the Saved Projects list, as well as the click-open info popovers) and fails if any part of its bubble, or its text, is cut off, runs past the screen, or is hidden by a clipping ancestor. Today the text-fit check (ticket 229) only opens the info popovers, so the other Tooltips are never looked at, and a new Tooltip can ship cut off without anyone noticing. After this ticket a new Tooltip that is cut off fails the build, the same way a new overflowing text does.

The goal is that no hover text can ever ship cut off, including ones that don't exist yet, so the check must not depend on a hand-kept list of triggers, and must fail when it cannot reach one. Three guards make it exhaustive:

1. **Discovery, not a list.** On each screen and state it visits, it finds every element that can show hover text from the page itself (every Tooltip trigger, every info popover, and any element with a native `title`), and opens each one. It does not name them.
2. **Reachability guard.** The source is the other half of the truth: every place in the app's source that uses the Tooltip (or an info popover) must be seen opened at least once in the run. A Tooltip that is in the source but was never opened (because its state, such as a Frame set, Row progress, a selection, a modal or a disabled button, isn't visited) fails the check and names the component, so the fix is to add the state, or to list it in a short, justified exemption list. Adding a Tooltip without a way to reach it cannot pass silently.
3. **One way to make hover text.** A cheap source check fails on a native `title` attribute used for hover text, and on any new hand-made tooltip or popover that does not go through the shared Tooltip or info popover, so a new kind of hover text can't bypass guards 1 and 2. The existing hand-made ones (the info popovers) are listed once, and are covered by the same measuring.

The check hovers each Tooltip trigger (and focuses it, since keyboard focus opens it too), in every language at every supported width, on every screen and state where triggers appear. It shares the text-fit check's screens and adds the states they lack: a Frame set (the Progress bar), a selection, each Tool group open, the drawer, each phone sheet, every menu and dialog, the New Project form, the empty library, the Saved Projects list. It measures, with no reference screenshots: the bubble's box against the screen, the bubble's box against every ancestor that clips it, and the bubble's own text against its box (wrapping, ellipsis, overflow). A failure names the screen, the trigger, the Tooltip's text, how many pixels are cut, the language and the width. The Tooltips that are cut off today (analysis below) are listed in the pending list, each to be deleted by ticket 265; an entry that stops failing fails the check until removed, as for text fit.

Found by a throwaway probe, at 1900, 1280, 1024, 768, 390, 360 and 320 px, English and Russian. Triggers that are measured as cut off today:
- Toolbox buttons (Paint, Fill, Select, Hand, Set Frame, and the other tools): the rich Tooltip (name, shortcut, description) is wider than the left column and the column clips it, at 768 to 1900 px.
- "No image colors" (the Image colors button): the long Tooltip is wider than the column that holds it, at 768 to 1900 px.
- Toolbox buttons in the narrow drawer (reported by the user with a screenshot; the throwaway probe did not catch it): the Hand tooltip, centered under a button near the card's left side, is cut off on the left by the tools card or drawer, which is well inside the screen. The Tooltip's own nudge only keeps the bubble inside the screen, so it does not help. The check must find this one itself; if it doesn't, it is not good enough. Exact width to be found when building the check.
- The Progress bar along the canvas (Row progress: the direction toggle, Row not done, Row done and their icon buttons; reported by the user with a screenshot; the probe never opened it): the Progress bar clips its overflow (`overflow: hidden`), so the Tooltip of a button in it shows only as a sliver of the bubble's edge. The check must reach this bar's state, which needs a Frame set, and find it itself.
- Zoom buttons on the desktop canvas (Zoom in, Zoom out, Reset zoom to fit): the canvas clips them at 768 to 1900 px, worst in Russian.
- The phone's zoom pill (Rulers, Zoom out, Zoom in, Reset zoom): the drawing area clips them at 390, 360 and 320 px.
- The tablet's bottom toolbar (Paint, Fill, Select, Eraser, Hand) at 768 px: the Tooltip opens below the button and is off the bottom of the screen.
- The compact Import file and Import QR code buttons on the phone's empty library: the Tooltip is off the bottom of the screen at 390, 360 and 320 px.

**Blocked by:** None (can start immediately).
