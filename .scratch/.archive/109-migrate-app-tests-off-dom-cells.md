# 109: Migrate the App-level tests off DOM cells

**What to build:** The app's main behaviour test suite stops finding beads as DOM elements and asserts the same behaviours through the renderer path instead. It is by far the largest batch of the migration (about 115 references to per-bead, per-row, preview and axis-line elements in a file of over 3,500 lines), so it is its own ticket. This is one batch of an expand–contract sequence: the DOM grid still exists, so the rest of the suite stays green while this batch moves. Ticket 111 deletes the old grid once every batch has moved.

Painting, erasing, Fill, Select, paste, Mirror, Row progress, Undo and Redo, hover previews and rotation are all still checked, by placing pointer events at coordinates on the Drawing surface and reading the result from the Pattern's state (and, for what is drawn, from the renderer's own output or the overlay's state), since the test environment has no real canvas.

**Blocked by:** 108 (Renderer becomes the default, and the cap goes)

**Status:** done

- [x] Every test in the App-level suite that finds beads, rows, preview markers or axis lines as DOM elements is re-expressed on the renderer path
- [x] No behaviour test is deleted without an equivalent: the list of behaviours the suite covered before is compared with the list after, and any that lost coverage are named in this ticket and closed
- [x] The suite is green, and no test in it depends on the temporary switch
- [x] Pointer events at coordinates go through the same hit-testing the app uses; a test helper for "press the bead at row r, column c" replaces the old element lookup

## How it came out

- **The helper** (`src/testUtils/beads.ts`, with `surfaceLayout.ts` giving the surface a box in jsdom): `pressBead(wrapper, at, { button, pointerType })` and `hoverBead(wrapper, at, { buttons })` put a pointer event at the coordinates of a bead, named by row and column or by its index along the rows (as a grid of elements was indexed), and the surface hit-tests it exactly as it does a real pointer (`rendering/hitTest.ts`, through every Technique, zoom and rotation); `leaveSurface`. What the app did is read from the state the surface is drawn from: `beadColor`/`beadColors`/`drawnPattern` (the Pattern), `selectedBeadCount`, `previewedBeads` (the hover preview: each bead with the color it shows, a bead with none is an outline and left out), `mirrorAxes`, `dimmedBeads`, `rowProgressView`. The surface gained `data-technique/columns/rows/rotated/zoom` on its root so a bead can be placed without knowing the Pattern. `clientX`/`clientY` joined the pointer-event properties `testSetup.ts` lets `@vue/test-utils` set.
- **`App.test.ts` (3,700 lines, 131 references) runs on the renderer**: 228 tests before and after, all green (292 test cases counting `each`), none deleted. About 100 `findAll('[data-testid="grid-cell"]')[n]!.trigger('pointerdown' | 'pointerenter')` became `pressBead`/`hoverBead`; every drag helper (Select, Del, clipboard, Mirror paste) is now press, move with the button held, release on the shell. Two tests that pressed several beads without releasing now release between presses (bead counts follow a stroke a few times a second since ticket 106; a click is a press and a release).
- **Before/after, by behaviour.** Each of these was asserted through elements and is asserted through state now, with what is drawn from that state covered where it belongs (renderer, overlay and surface unit tests, and the browser checks against ticket 103's references), so none lost coverage: the Pattern drawn has its rows and columns (was: counting row and cell elements, in three tests; now `drawnPattern` dimensions — the assertion that the count of elements equals the Pattern's size has no counterpart, since there are no such elements); a painted bead shows its color (was: the element's background style; now `beadColor`, and the drawn color is the renderer's tests and the census in the browser check); the hover preview appears where the pointer is, in the paint color, mirrored, in a pasted block's own colors, and clears on leave or Escape (was: preview elements; now `previewedBeads`); the Selection covers the right beads and goes on Escape, Copy, Del and Resize (was: a class on each cell; now `selectedBeadCount`); Row progress dims the rows or columns behind the pointer and outlines the current one, and survives a reload and an import (was: row and cell classes; now `rowProgressView`, the pointer's row or column and how many are behind it); a right click on the Pattern does not open the browser's menu; a Fill, a right-button erase, a touch stroke cancelled mid-drag, the locked finished rows and every Mirror and paste flow are unchanged, being driven and read the same way.
- **Named as not covered at this level, and covered elsewhere:** that the exact pixels drawn for a preview, a dimmed row or a marker are right. The App-level suite never could see them in jsdom (it read a class, not a look); they are the overlay and renderer unit tests and the 135 browser checks against the DOM references.
