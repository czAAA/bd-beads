# 14: Перестроить каркас приложения в layout инструментального приложения

**Что нужно сделать:** Реорганизовать текущий layout приложения в трёхпанельный каркас инструментального приложения — верхняя панель, левая панель инструментов, центральный холст, правая контекстная панель — по духу приложенного скриншота-референса (обычное приложение для рисования). Заимствовать у референса только *структуру*, а не набор функций: у bd-beads другой, более узкий функциональный охват, и новый layout должен показывать ровно этот охват и ничего лишнего.

**Целевой layout (только функции bd-beads):**
- **Верхняя панель:** название приложения, индикатор текущей схемы (название/сводка, тикет 05), переключатель языка (тикет 03)
- **Левая панель — инструменты:** выбор цвета из палитры и инструмент рисования (тикет 07), заливка (тикет 08), переключатели осей зеркала (тикет 09), отмена/повтор (тикет 07), настройки техники/размера холста (тикеты 01, 06), очистка/сброс
- **Центр:** сетка/холст схемы
- **Правая панель — контекстная:** список сохранённых схем/переключатель (тикет 05), переключатель прогресса по рядам (тикет 13), каталог бисера и сводка по количеству бисера на цвет (тикеты 10, 11), действия экспорта/импорта (тикет 12)

**Явно вне рамок задачи** (есть на скриншоте-референсе, но не относится к bd-beads): логин/регистрация, галерея, "Animate", загрузка/библиотека/объекты изображений, обобщённая панель слоёв, управление клонированием/отражением объектов, тенью, прозрачностью.

**Блокируется:** 01, 02

**Статус:** ready-for-agent

- [ ] Каркас приложения рендерится как четыре области, соответствующие структуре референса: верхняя панель, левая панель инструментов, центральный холст, правая контекстная панель
- [ ] Каждый элемент управления в новом layout соответствует существующей или запланированной функции bd-beads согласно целевому layout выше; ни одна из явно исключённых функций референса не добавляется
- [ ] Весь уже работающий функционал (рисование схемы, переключение схем, i18n и т.д.) продолжает работать после переноса — это реорганизация существующего/запланированного интерфейса, а не разработка новых функций
- [ ] Если функция ещё не реализована в своём тикете, для неё просто нет элемента управления в каркасе — без заглушек/placeholder'ов
- [ ] Layout использует дизайн-токены из тикета 02, а не разовые стили
