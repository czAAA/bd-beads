**Done (ticket 152), partial — set to ready-for-human rather than done:** removed `src/style.css`'s ticket-02 stylesheet (`--color-*`, `--border-width`, `--legacy-*`, `--radius-pill`, the old system font stack, and the unstyled `<button>`/`<input>`/`<label>`/`.icon-button`/`.button--danger` rules that shaped them) down to the two declarations still needed — the root's own `--font-size-base`/`--line-height-base` (nothing in the design system sets the page's base type; `e2e/support/app.ts` pins the line height for the visual checks) and the base color/background. `styles/tokens.test.ts`'s "still exist beside the new ones" guard now asserts the opposite: they're gone. The only real fallout was `SizeControls.vue` (the Toolbox's Size group), which had never moved off the ticket-02 look: its stepper buttons now match Mirror's (`AppButton variant="toolbox" size="sm"`, already the established pattern there), and its info glyph, tooltip, "change from" pills, error text and "Change size…" button (kept as a plain `aria-disabled` button, not `AppButton`, since it must stay focusable while Row progress locks it) now use design tokens. Caught a real bug removing the base declaration: the root's `font` shorthand referenced `--font-size-base`/`--line-height-base` without defining them anywhere once they left this file, silently falling back to the browser default font and throwing off enough layout to fail 28 of the visual regression suite's canvas "look" screenshots (peyote and brick specifically, both offset-row techniques) — found by bisecting against the ticket 165 commit, fixed by keeping the two declarations. Full `vitest`, `vue-tsc` and `eslint` runs are clean; the Playwright visual suite is back to its 5 pre-existing failures (unrelated: `framing.spec.ts` screenshot drift and `large-patterns.spec.ts` export timeouts, both reproducing identically on the ticket-163 baseline, so not this ticket's doing).

**What this pass did not do:** a full pixel audit against the approved screenshots, a theme-by-theme/card-by-card walk of every Derived area, a 200% zoom and high-contrast recheck, and a component-by-component match against every card — the checklist items above marked "not done this pass". That is genuinely the bulk of what "audit" means here and is a multi-session, largely human-eyes task; scoped out given the size of the rest of this batch (163–168, 79). SizeControls turned up by grepping for the tokens being deleted, not by a visual walk, so there may be other Derived-area gaps like it still to find.
