# Coding standards

What a change in this repo must follow, for whoever writes it and whoever reviews it. Each rule points to the ADR or doc that explains it; read that before arguing with the rule. Words for domain concepts come from [`CONTEXT.md`](CONTEXT.md); how things look comes from [`DESIGN.md`](DESIGN.md). Testing has its own page: [`docs/testing.md`](docs/testing.md).

## Where new code goes

- **Layers** (ADR 0020): `domain/` is pure TypeScript (no Vue, no browser globals, no `i18n/`); `services/` is the only code that reaches outside the page (storage, files, download); `composables/` call domain and services; `components/` never import services, they emit events or take what they need from props; `rendering/` draws on a canvas with no Vue and no services.
- **Feature folders** (ADR 0020): `components/<feature>/` and `composables/<feature>/`, with features `canvas`, `tools`, `palette`, `export`, `import`, `project`, `shell`. `components/ui/` holds the primitives and imports from no feature folder. No composable imports from a component, types included.
- **App.vue stays a composition root** (ADR 0020): new behavior is a composable (a user flow is a `use<Name>Flow`) wired in `useAppShell`, not logic in `App.vue` or `AppShell.vue`. CSS moves with its markup.
- **Each shell part takes only its own context** (ticket 0618, refining ADR 0020): `useAppShell` hands AppShell, CanvasPanel, AppPanels and AppDialogs one context each (`useShellFrame`, `useCanvasContext`, `usePanelsContext`, `useDialogsContext`); a name a part draws is added to its own context, never a flat one they all share.
- **A dialog opens through the registry** (ticket 0618, refining ADR 0020): its flow takes `dialogs` (from `useDialogs`) and holds its question in `dialogs.question(id)`, or `dialogs.flag(id)` when it asks about nothing; AppDialogs draws it while `open` names it. A flow given no `dialogs` makes its own registry, for its test alone; `useAppShell` passes the shared one to every flow. No dialog keeps an open flag outside the registry, and nothing ORs them: the keyboard shortcuts wait while `open` is set.
- Browser-only parts of the theme and language live in `theme/` and `i18n/`; the marketing page in `homepage/`.
- **The backend Worker is `worker/`** (ticket 71, spec 385), outside the app's layers: its own `tsconfig.json` (Workers types, no DOM), and nothing in `src/` imports it (lint). A route goes in `worker/src/index.ts`'s route list, refuses only through `ApiError`'s codes (`errors.ts`), and is guarded from `guards.ts`: `turnstile` on sign-up, sign-in and making a View link, `sizeCap` and `blobStorageLimit` on uploads, `rateLimit` with a binding the feature declares. Bodies are read only through `body.ts`, blobs stored only through `blobs.ts`. A feature registers its kill-switch name in `worker/src/features.ts` and in `docs/operations.md`; a limit or warn level is a variable in both environments of `wrangler.jsonc`, never a constant; a table is a numbered migration in its database's folder under `worker/migrations/`, which only adds. How it deploys: `docs/deploy.md`.

## Rules every change keeps

- **Every undoable change goes through `edit`** (ADR 0036): a flow receives `edit` (from `useEdit`) and calls `edit(kind, project => result)` with kind `drawing`, `frame` or `exempt`. It never calls `replaceProject` or records history itself, and never re-checks the Row progress lock or the margin (ask `mayPlace`; `keepAllowedEdits` also keeps beads out where the Weave has none).
- **Controls come from the registry and the shared components** (ADR 0035): an action is defined once in `composables/shell/controlRegistry.ts` (id, icon, name, Tooltip body, keys, `enabled`, `disabledBody`, `run`), and its keyboard shortcut comes from there. Render it with `IconButton`, `AppButton`, `MenuButton`, `AppSwitch` (an on/off) or `AppSwatch` from `components/ui/`; text that must always be readable is an `AppNote`. No native `title`, no hand-built tooltip; a control that can be disabled gives a `disabledBody` and uses `aria-disabled`.
- **Every user-facing string is in every language** (English, Russian, Ukrainian, Belarusian, Chinese, Spanish, Polish): add the key to the `Translations` interface in `src/i18n/translations.ts`, then to `en.ts`, `ru.ts`, `uk.ts`, `be.ts`, `zh.ts`, `es.ts` and `pl.ts` (a missing one fails the type check). A registry entry's name (a Technique's, a Form factor's, a Brand color's, a Starter's) is a plain key in the open `techniques`, `formFactors`, `colorNames` or `starters.options` group instead, so a new entry needs no type to change; `src/i18n/registryNames.test.ts` fails on one missing from any language (ADR 0078). A counted word lists the forms its language needs (`one`/`other` for English, `one`/`few`/`many` for Russian, Ukrainian, Belarusian and Polish, `one`/`many`/`other` for Spanish, `other` for Chinese). Counts go through `plural()`, and a string's blanks (`{count}`, `{name}`) are filled by `fillBlanks` (`domain/fillBlanks.ts`, ticket 0614), never by `.replace`: it fails in development and tests on a blank with no value or a value with no blank. Wording follows the design system's [`writing.md`](docs/design/system/writing.md), including its Russian section. Tickets, code and comments are English only.
- **No hardcoded colors, fonts, sizes or shadows**: use the role-named tokens (`docs/design/system/tokens.json`, as CSS custom properties from `src/styles/`). A need the design system doesn't cover is added to it in the same commit (`DESIGN.md` §6). Icons, logo and favicon come from `docs/design/system/`, never redrawn.
- **A panel is a descriptor and its content** (tickets 510, 511): Menu, Project and the Frame panel are entries in `components/shell/panels.ts`, mounted through `PanelHost` in `AppPanels`, never from inside the canvas. Placement (a dropdown under its button, at every width) is `AppPanel`'s alone; a new panel adds a descriptor and its content, no placement code.
- **Nothing raises a touch keyboard by itself** (ticket 520): a text field is focused through `TextField`'s `focus({ select, asked })` (`asked` when a tap opened it), never a native `.focus()` on a field, `.select()`, `createElement('input')`, `h('input')` or `contenteditable`; lint (`keyboard/no-self-raised-keyboard`) forbids them everywhere except `TextField.vue` and `services/touchFocusGuard.ts` (allowlist in `eslint.config.js`; it matches a focus receiver by name, `input`/`field`/`textarea`/`getElementById`). `touchFocusGuard`, installed in `main.ts`, is the runtime backstop: on touch a programmatic focus of a text field with no press or key in the last second is ignored.
- **An overlay is a layer in the registry** (ADR 0061): a sheet, panel, popover, menu or modal calls `useOverlayLayer` from `composables/ui/`, which owns Escape and the press outside (closes only the top-most layer, swallows the press and its click). No other code listens to a raw document or window `pointerdown`, `mousedown` or `click`; lint forbids it outside the registry and the canvas gesture code.
- **Text entry goes through `<TextField>`** (ticket 519): a bare `<input>` or `<textarea>` fails lint, so the keyboard handling (no keyboard raised on touch, Enter and Escape) stays in one place. Only the file components may hold `<input type="file">`, as it opens a picker, not a keyboard.
- **Each behavior is asserted at one level** (ticket 0599): the rule in the domain test, what a flow decides in its flow test, what a component shows and emits in its own, and only the wiring (a control reaches its flow) in an App test. Don't repeat at a higher level what a lower one proves (`docs/testing.md`, Where a test goes).
- **Stored data stays readable**: a change to how a Project or library is saved or encoded keeps every old format opening (see `docs/testing.md`, Stored-data compatibility).
- **A decision that a later reader would question gets an ADR** (`docs/adr/`, next free number, see `docs/agents/domain.md`); a contradiction with an existing ADR is called out, not made silently.

## Naming and comments

- Name things with the glossary's terms (`docs/glossary/`): Project, Schema, Canvas, Frame, Piece, Layer, Weave, Bead, Palette, Row progress. Code identifiers use US spelling (`color`); UI copy follows `writing.md`.
- Composables are `use<Name>`; a flow's dependencies come in as one `<Name>Deps` object. Components are PascalCase and multi-word.
- Every exported function, composable and component gets a short `/** */` comment saying what it is for and why, in domain words, citing the ticket or ADR when the reason lives there (see `useRotateFlow.ts`). Don't comment what the code already says; don't leave commented-out code or TODOs without a ticket number.
- A comment block (`//` run or `/* */`) is at most 3 lines: the non-obvious why, no restating the code or retelling history. A longer one needs the maintainer's approval and the word `approved-long` in it; lint enforces this (ticket 472).
- Match the file you're in: long lines (about 120 characters), no semicolons, single quotes, `import type` for types.

## Already enforced, so reviewers skip them

- **ESLint** (`npm run lint`, `eslint.config.js`): the typescript-eslint recommended set and Vue essential rules; unused variables (prefix `_` for a deliberate one); multi-word component names; the layer boundaries above, a blank filled by `.replace('{…}')` instead of `fillBlanks`, no raw document `pointerdown`/`mousedown`/`click` listener outside the overlay registry and the canvas gestures (`domain/` imports no Vue, services or UI and touches no `window`, `navigator`, `localStorage`, `fetch` or `document`; `rendering/` imports no Vue or services; `components/` import no services; `components/ui/` imports no feature folder).
- **The type check** (`npm run typecheck`): a translation missing in either language, an undoable flow reaching for `replaceProject`.
- **Unit tests that guard rules**: a Technique, Form factor, Brand color or Starter named in no language (`registryNames.test.ts`); in `controlRegistry.test.ts`, two actions with the same key, an action without a name in both languages, a disableable action without a `disabledBody`, a Tooltip body that isn't one sentence ending in a full stop; token values out of step with the design system (`src/styles/tokens.test.ts`); the RU file using an em dash (`useI18n.test.ts`); a language whose string has other blanks than English's (`src/i18n/blanks.test.ts`).
- **The text fit checks**: a label wider than its room, text or a Tooltip cut off in any language or width, a component with text that no browser fit test mounts, and hover text made any way but the Tooltip (`docs/testing.md`, Text fit checks).
- **knip** (`npm run knip`, run by CI with lint and by `npm run check`): unused files, exports and dependencies. Its second run, `knip --production`, leaves the tests out and fails on a file or export only tests reach: delete it, move a fixture builder into `src/testUtils/`, or, for an export the app keeps that a test names on purpose, tag it `@internal` in its doc comment with the reason (`docs/testing.md`, Shared test helpers).
