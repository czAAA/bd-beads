# ConfirmDialogs

The Delete all? and Replace bead? confirmations.

- The Modal template with the app's own copy: a destructive confirm is danger-filled (Delete all), any other is primary (Replace bead). Cancel is always on the left and has focus first.
- A side action (Save Project file, Save first) sits at the left of the row. When the row is too narrow for all three, the side action keeps the first row to itself and Cancel and the confirm move down together, side by side (ticket 0994).

Hand-written from the Phase A sign-off (forms, screens and states); static rendition.

- **Duplicate Project** and **Delete “{name}”?** (spec 0440, tickets 0443, 0842; copy and fields in the ProjectPanel card). Duplicate is a primary confirm with a TextField "Name" (suggestion "Moth 2", placeholder "Project name", the name counter from 30 characters on, hint "Suggested: the current name and the next free number.") that has focus first with its text selected; Enter confirms, Cancel leaves everything as it was. Delete is the one question of every delete of a Project, from the Projects library's ×, the Project panel's Delete Project and the notice of a Project that didn't open alike: it names the Project in its title and body, says to save its Project file first, and has the side action **Save Project file** (in-box, at the left), Cancel (focus first) and a danger-filled "Delete Project". Save Project file saves that Project's file as the Project panel's row does and leaves the dialog open. After Delete the most recently updated other Project opens; with none left, the empty Canvas (EmptyCanvas card); a toast with Undo says what happened (Message card, Project deleted; ticket 0983).
- **Delete all {count} Projects?** (tickets 443, 0984): asked by the Projects library's Delete all Projects. Its title names how many go, sealed Projects too ("Delete all 7 Projects?"; "Delete 1 Project?"), its message says it can't be undone and to save them first, and it has the side action **Save all Projects to a Project file** (in-box, at the left), Cancel (focus first) and a danger-filled "Delete all Projects". Save all saves the library's one file as the library's row does and leaves the dialog open.
- **Replace bead?** (tickets 0665, 0687; ADR 0079): each layer has its own Bead, picked in its own Layer settings (LayerSettings card): Project's canvas section the Canvas's, the Frame panel the Frame's. The dialog asks no layer. Its message names the layer and both Beads' sizes in mm, then says it looks different in proportion but the design and its bead count stay, and that it can be undone: "The Canvas's Bead changes from 1.5 × 1.5 mm to 1.7 × 2.2 mm. The Canvas will look different in proportion, but your design and its bead count stay exactly the same. You can undo this." The Frame's adds its Estimated size with the new Bead and the old, always in mm: "…, so the Frame will be about 16.5 × 44 mm instead of 15 × 30 mm. It will look different in proportion, …".
- **Open “{name}”?** (ticket 0716): picking a Project over the size gate asks first, a plain (not danger) confirm: "31 million beads. Opening may be slow or fail." (the count in whole millions from ten million, one decimal under it, cut down), **Open anyway** and Cancel.
- **Leave the converter?** (ticket 0756, ADR 0086): asked over the Convert image page by Close, Escape or a Menu action that leaves, once a picture is set. A destructive confirm: the message "Everything you set up here will be lost.", danger-filled **Leave**, and **Back to converter** on the left with focus first, so Escape and a stray Enter keep the work. Not undoable, as nothing has been added to a Project.
- **Remove Frame?** (ticket 0489, ADR 0066): a destructive confirm (danger-filled "Remove Frame", Cancel on the left with focus first) whose message says the beads stay: "Rows marked done will be cleared with the Frame. Its beads stay on the Canvas. This can be undone." The Frame's beads stay where they are, on the Canvas; one Undo brings back the Frame and the marked rows.
- **Open “{name}”?** after Open Project file with a Project open (tickets 154, 0860): what came in is already in the Projects library, so the question is only where to be. A plain confirm, **Open** and **Stay here** (left, focus first; Escape stays); the name is in the title, as a 40-character one doesn't fit a button. Its message: "“Fox” is now in the Projects library. Your progress on “Moth” is saved."; a file whose name the library holds came in under Duplicate's rule, and the message says so in one sentence: "“Summer bracelet” is already in the Projects library, so the file came in as “Summer bracelet 2”.". While the last save failed it says the open Project is not saved and offers **Save current** and **Switch anyway**. A Project in the file whose name is only spaces comes in under the name a Project left unnamed takes, "Project 1" or the next free number (ticket 0988), so no row and no question shows a blank name.
- **Switch Project?** (tickets 232, 0860): a pick in the Projects library opens at once, as nothing can be lost; the question comes only while the last save failed: "“Moth” is not saved in this browser yet. Save it first, or switch anyway and risk losing your latest change.", **Save first** (side action; once it gets through the switch goes ahead), Keep current (focus first) and **Switch anyway**.
- **Reset progress?** (tickets 0455, 0979; ProgressBar card): a destructive confirm (danger-filled "Reset progress", Cancel on the left with focus first). Reset is not an Undo step, so its message says what brings the rows back: "Every row marked done is cleared and you start again from the first row. The beads stay. Undo does not bring the marks back; Go to row does."
- **Clear all beads?** (ticket 0979; the Project panel's Clear all beads): a destructive confirm (danger-filled "Clear all beads", Cancel on the left with focus first) that says beads, never cells: "Every bead of this Project is removed and Row progress is turned off. Undo brings them back." One Undo brings back the beads and the rows marked done.
