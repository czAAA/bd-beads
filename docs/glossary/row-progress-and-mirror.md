# Glossary: Row progress and Mirror

Row progress and its Pass, direction and bar; the Mirror drawing aid. Part of the glossary split out of `CONTEXT.md` (ticket 380); the index is [README.md](README.md).

**Row progress**: It works on the Frame's rows only (the finished-row lock covers the Frame only); it is on exactly when the Project has a Frame (ticket 426, ADR 0055), and with none the Progress bar offers Fit to drawing.
An overlay on top of the project editor (not a separate mode) that tracks which rows have already been woven: a sequential "current row" pointer, movable backward, with finished rows shown slightly dimmed (never grey) and restored to normal color while the pointer hovers a finished row or after a tap on a finished row (a view setting, not saved and not an Undo step), the beads of the current row drawn 10% brighter, lifted above their neighbours and each ringed in the marker color, and remaining rows in normal colors (tickets 352, 376). Finished rows are locked: no drawing command (Paint, erase, Fill, Paste, Mirror) changes them, though Undo still restores an earlier grid in full. Clear project is the exception: it resets the passes along with the grid. The Frame cannot be resized (it can still be moved by the Move handle, with the pointer travelling with it), and Rotate, Remove row/column and the Technique wait, once a pass is done (ticket 411); until then they all work, so a Frame still being sized is no trap. Remove frame or Clear project unlocks its size. There is no switch for the mechanic and nothing stored: Row progress is on whenever there is a Frame, worked out from it everywhere (`rowProgressOn`), the pointer at the first pass from the Frame's Set, in the same Undo step as that Set Frame, and it goes with the Frame. Only its look can be switched off, by the Progress bar's Row highlight toggle (ticket 0474, ADR 0064): off, the Canvas draws no dimming of finished rows and no current-row ring, lift or brightening, while the pointer, the counter, the buttons and the finished-row lock all work; it is a view setting kept on the device, not in the Project and not an Undo step. Remove frame clears the passes with the Frame, so once a pass is done it asks first (`frameChangeDiscardsProgress`), and one Undo brings the Frame and its passes back. An old file's saved `enabled` flag is ignored and no file written carries it, so one saved with a Frame and Row progress off opens with it on (ticket 434). Exports draw without row marks. The pointer counts from the first pass to one past the last: when every pass is done the track is completely full and no pass is current. The marker, the lift and the brightening show only on cells that hold a bead; a pass with no beads shows none and the pointer still moves through it. Saved together with the project. Every control for it — Remove frame, Row direction, the pointer readout and the buttons that move the pointer — lives in the Progress bar along the canvas box's bottom edge (ticket 144).
_Avoid_: progress bar (as a name for this overlay/mechanic — it isn't a fill/percentage visualization, which is exactly what "Progress bar" is reserved for instead, see Progress bar), completion state

**Pass** (ticket 347): what Row progress's pointer counts. A line is a row or a column of the Frame, whichever way the weaver's rows run. On loom and brick stitch a pass is one whole line. On peyote the first line is one pass, and every later line takes two, each adding every other bead of it: the beads at even positions along the line first (the larger half on an odd line), then the odd ones. A 7-bead line is woven as 7, 4, 3, 4, 3, ... beads; an 8-bead line as 8, 4, 4, 4, .... The current-row marker is a ring round each bead the pass weaves, and only those (ticket 376), finished passes dim and lock only their own beads, and the Progress bar and rulers count passes and lines accordingly. A peyote Project saved before this keeps its pointer number, which now counts passes. In Right-angle weave a pass is one line of Units, every bead of it. In Netting (ticket 487) a pass is one row of diamonds: the first takes every bead of its row, each later one the beads below the row the one before ended on (the lower sides of its diamonds, their shared beads included), so each bead is woven once; Row direction stays on rows.
_Avoid_: half-row, sub-row (a pass is the word; "row" and "line" keep meaning the whole row or column)

**Row direction**:
Which way the weaver's rows run across a Project's grid for Row progress: along the grid's rows, or down its columns. Each direction keeps its own current-row pointer. Turning it shows a short success toast naming the new direction (once per change, the `D` key included), and the Progress bar's Row done and Row not done buttons take its label and arrow: "Row done ↓" and "Row not done ↑" top to bottom, "Column done →" and "Column not done ←" left to right (ticket 411). Independent of rotating the Project, which only turns the picture on screen: after rotating, the weaver flips Row direction too, but neither ever changes the other.
_Avoid_: progress orientation, row rotation

**Progress bar**:
The short bar along the canvas box's bottom edge that holds every Row progress control (ticket 144, reshaped by 411): Turn row direction, Row highlight (an on/off Switch, on by default, that shows or hides the Row progress look on the Canvas; ticket 0474, ADR 0064) and Reset progress (asks first, then takes the pointers back to the first row; disabled until a row is done; ticket 0455), the row counter, a track filled with the finished share, and the large text buttons Row not done (moves the pointer back one) and Row done (marks the row finished and moves on), set apart from Turn row direction so it can't be hit by accident. It is always there while a Project is open, at every width including under 1024px, whatever the Project's shape, so the canvas never jumps (ticket 426); with no Frame it shows Fit to drawing, and keeps its height. The `P` key is gone. Separate from the Row progress marker drawn on the grid (the current-row outline).
_Avoid_: progress control, row control

**Mirror**:
A symmetric-drawing aid for a Project. Each direction (left–right and top–bottom) has its own count of Mirror axes, from 0 (off) up to one fewer than the cells across that direction. N axes split the grid into N+1 equal strips (an axis may run through the middle of a cell, which then mirrors onto itself); painting a cell with the Paint tool also paints its counterpart in every other strip. By default neighbouring strips are mirror images of each other (A | A′ | A); a copy mode, one switch for both directions, instead repeats the strip unflipped (A | A | A). Directions are as seen on screen, so rotating the Project swaps the two counts. Axes are drawn as faint lines on the canvas while either count is above 0. A separate "Mirror current" action per direction does a one-time sync of what's already painted, copying the strip with the most painted cells onto the rest (1 center axis if that direction's count is 0), honouring copy mode; hovering it shows the axes and dims the cells it would overwrite. Axis counts and copy mode are an editing-session setting, reset when switching Projects or when the Frame changes. Fill and Clear project are not affected by Mirror; Paste now is — see Paste.
_Avoid_: reflect, symmetry mode, apply mirror
