# Glossary: Row progress

Row progress and its Pass, direction and strip. Part of the glossary split out of `CONTEXT.md` (ticket 380); the index is [README.md](README.md).

**Row progress**: It works on a Frame's rows only (the finished-row lock covers that Frame only); it is on for every Frame, each with its own pointers and passes (ticket 426, ADR 0055; spec 1214), and with none there is no strip, the Project panel offering the ways to add a Frame.
An overlay on top of the project editor (not a separate mode) that tracks which rows have already been woven: a sequential "current row" pointer, movable backward, with finished rows shown slightly dimmed (never grey) and restored to normal color while the pointer hovers a finished row or after a tap on a finished row (a view setting, not saved and not an Undo step), the beads of the current row raised, in their own color above their neighbours, 1px larger on every side on one soft shadow (ticket 1032), and each ringed by two lines on its raised edge, the marker color with a 1px line of the page color (`canvas`) inside it so one of them reads on a bead of any color (ticket 1031), and remaining rows in normal colors (tickets 352, 376). Finished rows are locked: no drawing command (Paint, erase, Fill, Paste, Mirror) changes them, though Undo still restores an earlier grid in full. A drawing they hold back says so in one toast a stroke, naming Back a row; what else waits names Reset progress (ticket 0848). On screen the state is "marked done", never "finished". Clear project is the exception: it resets the passes along with the grid. The Frame cannot be resized and its Technique's settings (a Drop) wait once a pass is done (ticket 411); until then they work, so a Frame still being sized is no trap. A change of its Technique with a pass done asks first (ticket 1184): start over for the new Technique (its own way as the Frame lies, every pointer at the first pass), keep the whole lines woven in the current way (each pointer at the first pass of the next line in the new Technique's passes, so a peyote line with only one of its two passes done goes back to its start; the dialog counts whole rows), or Cancel. A Custom frame's Technique still waits. The Frame can still be moved by the Move handle, with the pointer travelling with it, and three changes keep what is woven (ticket 0647, ADR 0055): Rotate Frame turns the Frame with its beads in their own rows (ticket 0667): with no pass done it just turns and the Row direction stays as seen (ticket 1183); with a pass done it asks first whether to start over in the way as seen or keep the rows woven, every pointer staying and the same beads staying finished with the Row direction turned along with the Frame (ticket 1184; and the Canvas's turn changes no pointer either, ticket 1101); Remove row/column asks first when it touches a finished pass, a finished row moving the pointer back by its passes and a column across finished rows leaving them finished; and Rotate of a Selection is held back only where the Selection reaches into finished rows. Remove frame or Clear project unlocks its size. There is no switch for the mechanic and nothing stored: Row progress is on whenever there is a Frame, worked out from it everywhere (`rowProgressOn`), the pointer at the first pass from the Frame's Set, in the same Undo step as that Set Frame, and it goes with the Frame. Only its look can be switched off, by Show row marks in the Row progress strip's list (Row highlight, ticket 0474, ADR 0055, 0973; the Progress bar's toggle until ticket 1223): off, the Canvas draws no dimming of finished rows and no current-row ring, raised bead or shadow, while the pointer, the counter, the buttons and the finished-row lock all work; it is a view setting kept on the device, not in the Project and not an Undo step. Remove frame clears the passes with the Frame; it always asks first, done passes or not (ticket 0669), and one Undo brings the Frame and its passes back. An old file's saved `enabled` flag is ignored and no file written carries it, so one saved with a Frame and Row progress off opens with it on (ticket 434). Exports draw without row marks. The pointer counts from the first pass to one past the last: when every pass is done the track is completely full and no pass is current. The marker and the lift show only on cells that hold a bead; a pass with no beads shows none and the pointer still moves through it. Saved together with the project. Every control for it — Row direction, Show row marks, Reset progress, the pointer readout and the buttons that move the pointer — lives in that Frame's Row progress strip on its Margin sheet (tickets 144, 1223), and Remove Frame is in its settings popover and the Frames section.
_Avoid_: progress bar (as a name for this overlay/mechanic — it isn't a fill/percentage visualization, which is exactly what "Progress bar" is reserved for instead, see Progress bar), completion state

**Pass** (ticket 347): what Row progress's pointer counts. A line is a row or a column of the Frame, whichever way the weaver's rows run. On loom and brick stitch a pass is one whole line, except a brick stitch Drop of N woven along its rows (top to bottom or bottom to top), where a pass is the N rows of a block together, all of them the current row: the blocks are the stagger's own, counted from the Frame's top, so woven from the bottom the first pass holds the few rows left over when the height is not a multiple of N; the ruler marks the first row of the block (ticket 0000). On peyote the first line is one pass, and every later line takes two, each adding every other bead of it (every other block of N beads at a Drop of N, picked up together), and always the half nearer the lines already woven first, so a pass never steps back (ticket 1154): woven top to bottom the level columns' beads and then the shifted ones', half a bead lower; woven bottom to top the shifted ones first. A 7-bead line is woven as 7, 4, 3, 4, 3, ... beads from the top and 7, 3, 4, 3, 4, ... from the bottom; an 8-bead line as 8, 4, 4, 4, .... Down a peyote Frame's columns, where a line's beads lie level, the even positions come first. The current-row marker is a ring round each bead the pass weaves, and only those (ticket 376), finished passes dim and lock only their own beads, and the Row progress strip and rulers count passes and lines accordingly. A peyote Project saved before this keeps its pointer number, which now counts passes.
_Avoid_: half-row, sub-row (a pass is the word; "row" and "line" keep meaning the whole row or column)

**Row order** (ticket 0591, ADR 0077): how Row progress steps through a Frame's beads, pass by pass: how many passes it takes, which pass weaves each bead, the beads of the pass the weaver is on, the line the rulers mark and whether Row direction can turn. Chosen by the Frame's shape and, for a Frame with none, its Technique; Row progress asks it and never the Technique. The **rows** order is the Frame as woven so far: one pass a line on loom and brick stitch (a brick stitch Drop of N woven along its rows one pass a block of N rows, see Pass), peyote's two passes after the first line. A Custom frame's order (ticket 0594) is **rounds** from the centre (Triangle, Warped Square), **rows** from a Kite's point (back and forth: an odd row from the left wing's end to the spine pair and out along the right, an even row back, ticket 0874), or for a Star or Kaleidocycle each part round by round in making order and then its **joins** (zips and the closing join, each ringing the edges it puts together; a Kaleidocycle's are the Kali Primer's, ticket 0877: each triangle zipped into its **Strip** of four and closed into a **Tetra**, the **Mirror pairs** 1–2, 3–4 and 5–6 laced with 15/0 **Hinge Pins** on the gaps between their triangles, then the three **ring** joins that put the pairs together, each named by its two pairs and made on Hinges of triangles off this face; only a Mirror pair's gap rings its edges, and the face's other three gaps have no join), each pass counted on from those before it, so a (part, step) pointer is one number; it is worked one way only, and the Word chart lists its passes in that order. A round is read as it is beaded (ticket 0873): after the step-up it starts with the **corner pair**, the two beads picked up together at the corner where the last side meets the first (one either side of their Seam), the same corner every round, and goes on side by side, each side a corner pair and then its single beads, so it ends on the last side's last single. Round 1, the ring, has no pairs; it starts on the last side's bead, which the step-up leads out of into round 2's first pair. A Fringe earring's order (ticket 0597) is its top's **rows** from the base row up, each read left to right, its body's rows before its point's (ticket 0814), in its Technique's own order as on a plain Frame: one pass a row on loom and on brick stitch (a block of Drop rows on a Drop), peyote's first line in one pass and each later line in two, the beads of its higher columns then those of the columns half a bead lower, the point's shorter lines included; then its **strands**, one pass each from the first on the left, strung top to bottom.
_Avoid_: row strategy, stitch order, sequence

**Row direction**:
Which way the weaver's rows run across the Frame for Row progress: four ways, top to bottom, left to right, bottom to top and right to left (ticket 0589), always named as the Frame lies on screen: top is the top, left is the left. The button and the `D` key turn through them in that order, as seen. The two reversed ways count their lines from the Frame's far edge (Row 1 is the bottom row, or the right column; the Word chart's header says so); the rulers on the Canvas do not follow it: they always count left to right and top to bottom as seen, whatever the way and whatever is turned, and the counter's row on peyote names the ruler's number of the current line (ticket 1165), so a Frame woven from its far edge starts on the last number. Whenever progress starts afresh the way is the Frame Technique's own, as the Frame lies then (spec 1182, ticket 1183): loom top to bottom, peyote left to right, brick stitch bottom to top, a Custom frame along its rows. One rule sets it, never the Canvas's Technique: a new Frame, Frame from Selection, Fit to drawing, a Starter, a new Project, Convert image, Delete all and a change of the Frame's Technique (with no pass done, or started over) all start there, whatever the way was and however often the Frame or the way was turned before, and the weaver can pick another after; a change of the Frame's settings alone keeps the way. Rotate Frame with no pass done keeps the way as seen: a Frame woven top to bottom is woven top to bottom after the turn; with a pass done it asks first whether to start over in that way or keep the rows, the way then turning along with the Frame (ticket 1184). Rotate canvas never touches it (ticket 1188): the Frame stays as it lies on screen, so its way, its words, the arrows and the toast stay as they were. Each of the four keeps its own current-row pointer. Turning it shows a short success toast naming the new direction (once per change, the `D` key included), and the strip's Row done and Back a row buttons take its label and arrow: "Row done ↓" and "Back a row ↑" top to bottom, "Column done →" and "Back a column ←" left to right, the arrows reversed for the other two (tickets 411, 0589). The noun is as seen too: top to bottom and bottom to top are rows, left to right and right to left columns, whatever the Frame's own lines are, in the label, the buttons, the list, the toast and the counter, so a turned loom Frame woven right to left reads "Column done ←". The Frame keeps the way as seen, on its nearest quarter turn, with a pointer for each way as seen (ticket 1185); its own axis and end (along its own rows or columns, from its first or its last), which its passes, the peyote counter's line, the Word chart's Row 1 and the ruler's pass marker go by, are worked out from that. A way chosen from the list runs that way on screen.
_Avoid_: progress orientation, row rotation

**Progress bar**:
The App page's footer (ADR 0085) of a page that goes by steps: along the canvas box's bottom edge, the sections on the Homepage and the five steps in Convert image (named dots, Back and Next). The editor has none: ticket 1223 retired the bar that held Row progress, and each Frame's **Row progress strip** (below) holds all of it. Separate from the Row progress marker drawn on the grid (the current-row outline).

**Row progress strip** (tickets 1176, 1223; spec 1214; MarginSheet card, "Several Frames"): the one Row progress, on each Frame's Margin sheet, so with several Frames each has its own and every control on it acts on its Frame alone. Full width of the sheet's bottom margin, under the title block (at the compact and folded zooms the title block's name tab shares its line, the strip taking what it leaves); left to right, Back a row (the quiet text button), the counter as a button (its list: the four ways with a check on the current one, Show row marks and Reset progress, which asks first and is off until a row is done; a Custom frame has no ways), the track filled with the finished share, and Row done (the one filled button, marks the row finished and moves on). Short of room the counter shortens to "5/30" first, then the track goes, then Back a row keeps its arrow alone; Row done is never dropped. One Tab stop, ←/→ along it. At the bare zoom nothing of the sheet is drawn, so the strip keeps its screen size and hangs centred 4px under the Frame's bottom line in the popover look. The Homepage's Welcome cuff and What's inside's demo show the same strip. The `P` key is gone.
_Avoid_: progress control, row control

**Pattern done** (tickets 0729, 0730):
What the Canvas plays once when a press of Row done marks the last pass: a silver firework over the Frame, a shimmer that brings the finished passes back to full color, and twinkling stars, over in about 3s, taking no press and never in exports. Not on opening a finished Project, Undo or Redo; Back a row stops it. Each Row done before it glints its pass, bead by bead, and flares the spark on the Row progress strip's track. Under reduced motion only the color comes back. See the design system's Motion section, Row progress. For as long as every pass is done the strip's counter reads Pattern done, with a check, in place of the count (ticket 0849); the counter is text, and no control sets a row by typing it.
_Avoid_: finish (a Bead color's Finish), celebration, confetti, party
