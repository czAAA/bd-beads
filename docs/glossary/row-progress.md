# Glossary: Row progress

Row progress and its Pass, direction and bar. Part of the glossary split out of `CONTEXT.md` (ticket 380); the index is [README.md](README.md).

**Row progress**: It works on the Frame's rows only (the finished-row lock covers the Frame only); it is on exactly when the Project has a Frame (ticket 426, ADR 0055), and with none the Progress bar offers Fit to drawing.
An overlay on top of the project editor (not a separate mode) that tracks which rows have already been woven: a sequential "current row" pointer, movable backward, with finished rows shown slightly dimmed (never grey) and restored to normal color while the pointer hovers a finished row or after a tap on a finished row (a view setting, not saved and not an Undo step), the beads of the current row drawn 10% brighter, lifted above their neighbours and each ringed in the marker color, and remaining rows in normal colors (tickets 352, 376). Finished rows are locked: no drawing command (Paint, erase, Fill, Paste, Mirror) changes them, though Undo still restores an earlier grid in full. Clear project is the exception: it resets the passes along with the grid. The Frame cannot be resized and its Technique waits once a pass is done (ticket 411); until then they work, so a Frame still being sized is no trap. The Frame can still be moved by the Move handle, with the pointer travelling with it, and three changes keep what is woven (ticket 0647, ADR 0055): Rotate Frame turns the Frame with its beads in their own rows (ticket 0667), so every pointer stays and the same beads stay finished, without asking, the Row direction shown turned with the Frame; Remove row/column asks first when it touches a finished pass, a finished row moving the pointer back by its passes and a column across finished rows leaving them finished; and Rotate of a Selection is held back only where the Selection reaches into finished rows. Remove frame or Clear project unlocks its size. There is no switch for the mechanic and nothing stored: Row progress is on whenever there is a Frame, worked out from it everywhere (`rowProgressOn`), the pointer at the first pass from the Frame's Set, in the same Undo step as that Set Frame, and it goes with the Frame. Only its look can be switched off, by the Progress bar's Row highlight toggle (ticket 0474, ADR 0055): off, the Canvas draws no dimming of finished rows and no current-row ring, lift or brightening, while the pointer, the counter, the buttons and the finished-row lock all work; it is a view setting kept on the device, not in the Project and not an Undo step. Remove frame clears the passes with the Frame; it always asks first, done passes or not (ticket 0669), and one Undo brings the Frame and its passes back. An old file's saved `enabled` flag is ignored and no file written carries it, so one saved with a Frame and Row progress off opens with it on (ticket 434). Exports draw without row marks. The pointer counts from the first pass to one past the last: when every pass is done the track is completely full and no pass is current. The marker, the lift and the brightening show only on cells that hold a bead; a pass with no beads shows none and the pointer still moves through it. Saved together with the project. Every control for it — Remove frame, Row direction, the pointer readout and the buttons that move the pointer — lives in the Progress bar along the canvas box's bottom edge (ticket 144).
_Avoid_: progress bar (as a name for this overlay/mechanic — it isn't a fill/percentage visualization, which is exactly what "Progress bar" is reserved for instead, see Progress bar), completion state

**Pass** (ticket 347): what Row progress's pointer counts. A line is a row or a column of the Frame, whichever way the weaver's rows run. On loom and brick stitch a pass is one whole line. On peyote the first line is one pass, and every later line takes two, each adding every other bead of it: the beads at even positions along the line first (the larger half on an odd line), then the odd ones. A 7-bead line is woven as 7, 4, 3, 4, 3, ... beads; an 8-bead line as 8, 4, 4, 4, .... The current-row marker is a ring round each bead the pass weaves, and only those (ticket 376), finished passes dim and lock only their own beads, and the Progress bar and rulers count passes and lines accordingly. A peyote Project saved before this keeps its pointer number, which now counts passes.
_Avoid_: half-row, sub-row (a pass is the word; "row" and "line" keep meaning the whole row or column)

**Row order** (ticket 0591, ADR 0077): how Row progress steps through a Frame's beads, pass by pass: how many passes it takes, which pass weaves each bead, the beads of the pass the weaver is on, the line the rulers mark and whether Row direction can turn. Chosen by the Frame's shape and, for a Frame with none, its Technique; Row progress asks it and never the Technique. The **rows** order is the Frame as woven so far: one pass a line on loom and brick stitch, peyote's two passes after the first line. A Custom frame's order (ticket 0594) is **rounds** from the centre (Triangle, Warped Square), **rows** from a Kite's point (each read left to right across its wings), or for a Star or Kaleidocycle each part round by round in making order and then its **joins** (zips, hinges and the closing joins, each ringing the edges it puts together), each pass counted on from those before it, so a (part, step) pointer is one number; it is worked one way only, and the Word chart lists its passes in that order. A Fringe earring's order (ticket 0597) is its top's **rows** from the base row up, each read left to right, then its **strands**, one pass each from the first on the left, strung top to bottom.
_Avoid_: row strategy, stitch order, sequence

**Row direction**:
Which way the weaver's rows run across a Project's grid for Row progress: four ways, top to bottom, left to right, bottom to top and right to left (ticket 0589); the button and the `D` key turn through them in that order. The two reversed ways count their lines from the Frame's far edge (Row 1 is the bottom row, or the right column; the Word chart's header says so). Each of the four keeps its own current-row pointer. Turning it shows a short success toast naming the new direction (once per change, the `D` key included), and the Progress bar's Row done and Row not done buttons take its label and arrow: "Row done ↓" and "Row not done ↑" top to bottom, "Column done →" and "Column not done ←" left to right, the arrows reversed for the other two (tickets 411, 0589). Independent of rotating the Project, which only turns the picture on screen: after rotating, the weaver flips Row direction too, but neither ever changes the other.
_Avoid_: progress orientation, row rotation

**Progress bar**:
The short bar that fills the Canvas footer, along the canvas box's bottom edge, and holds every Row progress control (ticket 144, reshaped by 411): Turn row direction, Row highlight (an on/off Switch, on by default, that shows or hides the Row progress look on the Canvas; ticket 0474, ADR 0055) and Reset progress (asks first, then takes the pointers back to the first row; disabled until a row is done; ticket 0455), the row counter, a track filled with the finished share, and the large text buttons Row not done (moves the pointer back one) and Row done (marks the row finished and moves on), set apart from Turn row direction so it can't be hit by accident. It is always there while a Project is open, at every width including under 1024px, whatever the Project's shape, so the canvas never jumps (ticket 426); with no Frame it shows Fit to drawing, and keeps its height. The `P` key is gone. Separate from the Row progress marker drawn on the grid (the current-row outline).
_Avoid_: progress control, row control

**Pattern done** (ticket 0729):
What the Canvas plays once when a press of Row done marks the last pass: a silver firework over the Frame, a shimmer that brings the finished passes back to full color, and twinkling stars, about 2.6s, taking no press and never in exports. Not on opening a finished Project, Undo or Redo; Row not done stops it. Each Row done before it glints its pass, bead by bead, and flares the spark on the Progress bar's track. Under reduced motion only the color comes back. See the design system's Motion section, Row progress.
_Avoid_: finish (a Bead color's Finish), celebration, confetti, party
