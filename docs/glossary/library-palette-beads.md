# Glossary: Library, Palette and Beads

The Project library, the Palette, Beads and their colors, Techniques. Part of the glossary split out of `CONTEXT.md` (ticket 380); the index is [README.md](README.md).

**Project library**:
Every Project saved on this device, taken together — what the Saved Projects box lists and what a library Project file (`openbeads_lib.openbeads`, gzipped; ADR 0048) exports in one go. It is ordered by last save, most recently saved first, with no grouping or nesting: saving a Project (any change to it, or Save) moves it to the front, a new or imported Project starts there, and a library saved before the order existed is put in order by when each Project was last changed (ticket 145). A Project belongs to the library from the moment it is created, and leaves it only by being removed. Lives only on the device that made it (ADR 0001), so moving it anywhere means exporting a Project file. Saves itself as it changes, so there is no Save button (ticket 523): the Project panel's save state says "saved · this device", or that the device refused, with Try again. Getting a Project onto another device is Export Project file (ticket 119). Every command persists the moment it lands, except a dragged paint or erase stroke, which is saved when the button is released. If a save doesn't get through — the browser's storage is full — the editor says so in a notice above the canvas and keeps the change on screen rather than losing it silently. Importing while a Project is open asks first whether to switch to the imported Project (saying the current one's progress is saved, or, after a failed save, offering to save it first); either way the imported Project joins the library, and with no Project open it opens without asking (ticket 154). The Saved Projects box asks too: the remove × asks "Remove this Project?" in a danger confirmation, and picking a different thumbnail asks "Switch Project?" naming both, with the same save-first offer after a failed save; picking the open Project does nothing (ticket 232). See ADR 0012.
_Avoid_: collection, gallery, saved list, workspace

**Offline copy**:
The app itself, kept on the device by the service worker after the first visit, so it opens with no internet or while our hosting is down (ticket 69, ADR 0045). It downloads silently; a newer one waits behind the open page until the person presses Reload in "Update ready", or the app is next opened. It holds no Projects: those are the Project library.
_Avoid_: cache, offline mode, downloaded app

**Keep note**:
The short note shown once per device, at the first time a Project is written to the library and only if the browser doesn't already keep it (ticket 399). It says in plain words that the browser may ask to keep this app's data, to tick "Remember this decision" and choose Allow so Projects survive a device short on space, and that after a decline Projects can still be cleared, so Save often and keep the Project file safe. Its button is what triggers the browser's own prompt; Skip doesn't ask the browser. Either way the device remembers it was shown. Opening the app never asks. A browser without the storage API, or one that decides silently, just never gets the note.
_Avoid_: permission prompt, storage popup

**Maker's name**:
Who made a Project: an optional name, at most 40 characters, printed on that Project's PDF and PNG exports as information (made by, the chart page header, "by" on the PNG; never as a watermark), alongside the Project's own name. It belongs to the Project, not to the device, so it is set per Project (the New Project form, then "Name on exports") and travels with the Project (export, import, another device); there is no device-wide name and no fallback, and an empty name leaves the exports without one (ADR 0060, tickets 161, 182, 441).
_Avoid_: author, owner, signature, user name

**Palette**:
A Project's own set of colors used to paint its cells: built-in colors that come from the Bead of the layer that is woven, the Frame's or else the Canvas's (ADR 0079; its Brand's color families, on the Brand row: Miyuki's 16 for a Miyuki Bead, otherwise twelve; data source in the research note `brand-color-groups-for-default-palettes`, ticket 0527; ticket 0528), followed by the Custom colors that have joined it (no cap), in slots, saved in the Project and in its `.openbeads` file, so it is the same on every device. A swatch can be dragged to another slot (or moved with Alt+Left/Right), built-in ones too, and a removed color's slot closes up, so the slots never have a gap. A Custom color joins the last slot when the Custom color picker is left with it or it is taken from the canvas with Pick color from canvas. An added swatch can be removed again (never a built-in one): by Delete or Backspace on a focused one, or in Edit palette; either way it asks for confirmation first, painted cells keep their color, and an Undo toast puts it back. Removing the active color steps back to the default color. Adding, removing and moving a swatch are Undo steps. A new Project starts with the built-in colors. What is stored is what is shown: a built-in color a Project's Palette leaves out stays out. Every reader (image conversion, the screen-reader announcer, Beads needed, the picker, the tooltips) asks the Project's Palette. A color's name is a translation (a generic color) or a literal (a brand's own), one lookup for both, "Custom color" for an added one; the default color is the first built-in swatch. A swatch picked from the Color catalog keeps its maker's code (by its hex, saved in the Project and in the file from version 8, ticket 0538); painted cells still store only their hex. Replace Bead keeps a swatch's code only if the new Bead's catalog lists it in the new size, the rest become plain colors, all in the same Undo step. Independent from the bead catalog — a cell's color is not required to correspond to a real bead. Colors have ten shortcuts, Shift+1…9 and Shift+0: Shift+1, 2 and 3 pick the Tool pill's three recent colors (the painting color left out), and Shift+4…9 and Shift+0 pick the first seven slots whose color is not one of those recents, whichever color stands in them. A color that is one of the three recents is shown only as a chip in the pill (the colour popover's Palette skips it) and returns to its slot when it drops out; the Palette itself keeps it. See ADR 0002.
_Avoid_: color scheme, fixed palette

**Swatch letter** (ticket 0573): the short label every Palette color carries, kept in the Project whether or not it is shown: A, B, C… then AA, AB… after Z. Given when the color joins the Palette (the lowest letter not in use) and never changed by reordering or deleting colors, so a printed sheet and the file stay in step; a Project saved before they existed is given letters in Palette order when opened. It is what the Letters toggle prints on the Frame's beads and what the Word chart and its legend use. Planned: choosing a custom one in the colors menu, unique within the Project, which then changes every place it shows.
_Avoid_: legend letter, symbol, code (a code is a Bead color's maker code)

**Edit palette**:
A mode of the Palette in the color popover, entered with the pencil in its head row (shown only while the Palette has a Custom color) and left with the pencil again, Escape, closing the popover, or removing the last Custom color. While it lasts, each Custom swatch carries a large × and a click (or Enter, Space, Delete, Backspace on a focused one) asks to remove that color instead of choosing it; the built-in swatches are faded with a tip that default colors can't be removed, and Pick color from canvas and Custom color are disabled. Dragging a swatch to another slot still works. A bin after the word Palette ("Remove all custom colors") asks to remove every Custom color at once, naming how many; one Undo toast puts them all back in their slots. Both removals are guarded by a confirmation.
_Avoid_: manage colors, delete mode

**Bead**:
A catalog entry for a real bead line: a Brand, a Form factor and a Bead size (e.g. Miyuki Delica 11/0), not a color (that is a Bead color), with its own physical footprint in mm (used to convert an mm/cm size into a grid when a Project is created, and to work out an Estimated size — see ticket 01), width correction and beads per kg for that combination (ADR 0072, ticket 533), so nothing about a Bead is derived from its size alone. Width runs along the thread (the bead's length through its hole) and height across it (its diameter), so TOHO Round 11/0 is 1.5 × 2.2mm, not a 2.2mm ball. A Bead may carry a per-bead width correction (mm added to each column for thread and slack, measured rather than published — currently 0.15mm on TOHO Round 11/0), so a column is `widthMm + widthCorrectionMm` wide. Beads per kg is the maker's published figure; grams per bead are derived from it, and a Bead without one shows no Estimated weight. Its id is built from its parts (`miyuki/delica/11-0`), never changed or reused; the three ids from before are read through an alias map, and a Bead that leaves the catalog stays in it, flagged retired. Each layer has its own Bead (ADR 0007, ADR 0079, ticket 0665), changed in its Layer settings, and saves a full copy of it and its Form factor in the Project file (file version 7, ticket 534) and reads everything from that copy (drawing, Estimated size, Beads needed, weight), so it opens and draws the same whatever the catalog later does; a file without a copy gets the catalog's Bead of its id on open, and an id nobody knows stays the unknown Bead. A retired Bead is offered nowhere (not New Project, Starter or Replace Bead) and stays in every file that has it. When the catalog's Bead of the same id differs from the copy in footprint, correction, outline, holes or beads per kg (names and labels do not count), Replace Bead lists the copy with an "(as saved)" postfix, not pickable, beside the catalog's current one; picking that one is an ordinary Replace Bead. The woven layer's Brand decides the Palette's built-in colors (`defaultPalette`, see Palette); changing that Bead moves the Palette with it, in the same Undo step. Each layer is drawn at its own Bead's real size, so a 15/0 Frame over an 11/0 Canvas looks smaller. The catalog is a fixed built-in list of 17 Beads (TOHO Cube 1.5mm; TOHO Round 15/0, 11/0, 10/0, 9/0, 8/0, 7/0, 6/0 and 3/0; Miyuki Delica 15/0, 11/0, 10/0 and 8/0; Miyuki Round 15/0, 11/0, 8/0 and 6/0), grown by adding data — see ADR 0007 and ADR 0072.
_Avoid_: seed bead type, item

**Bead color**:
One real color of a Bead line, identified by its maker's code (e.g. Delica `DB1`) and described by facts only: the maker's color family, a **Finish** and the Bead sizes it exists in, with a discontinued flag. No photo or durability rating is kept, and a hex only where a human has measured one (ADR 0072, ticket 536). In the color popover, "Bead colors" opens the catalog of the woven layer's Bead for its Bead size: each code is a swatch made from the color family and the Finish and shown as approximate (a measured hex replaces it), a discontinued code is marked, and a code whose hex the Palette already holds is shown as taken and cannot be added twice. Adding one is an Edit and the swatch joins as an added color; a Mix has no single color and is not listed (ticket 537). The list's search finds a code as a part of a maker code or of a family name, or typed the way a shop writes it (ticket 0696, `domain/beadCodeSearch.ts`): `DB-0433`, `DB0433` and `db 433` find Delica `DB433`; `#1F`, `11-1F` and `RR11-0001F` find Round `1F`; `TO11R49` and `11-49` find TOHO `49`. A `#`, a retailer prefix (`N-`, `RR`, `TO`), a size prefix of the Bead's own size, a dash or space after the letters and the number's leading zeros are dropped; a prefix of another size or Brand is not a match. The code's shape follows the Color catalog, not the Brand, as Miyuki keys Delica and Round differently while TOHO's shapes share one series. A partly typed code is normalized the same way and matched as a prefix (ticket 0713, `domain/beadColorFilter.ts`): `DB-04` lists DB4, DB40, DB43, DB433… and `11-4` on a TOHO 11/0 lists 4, 40, 41, 49…. The matches come in groups, each in catalog order: the exact code, the codes it is a prefix of, the codes the raw text is a part of, then the family-name matches, so DB433 is first while it is being typed. Under the search two **filter** rows narrow the list the way a maker's or a shop's site does: Color (the Brand's color families that have a code in the Bead's size, each as its family swatch) and Finish (the shared Finishes present, as text chips); several values of a row may be on at once, the rows combine with each other and with the search, and each value shows its live count (the rows it would show given everything else that is on; a value with none is dimmed but still pressable). Brand, Form factor and size are not filters, since a layer has one Bead (ADR 0007); discontinued codes stay shown and marked; the filters reset when the list closes or the Bead is replaced and are not saved. When nothing matches, one sentence names what is on ("No matte Blue codes match DB4") and Clear filters turns every value off, keeping the search text; a typed code that the catalog has but not in this Bead's size gets its sizes instead ("4 exists in 15/0, 11/0, and 8/0, not in 6/0"); there is no hint across catalogs. The same list with the same filters is the Convert image wizard's remap picker. The word in the UI is "filter"; "facet" appears nowhere a person sees.
_Avoid_: bead shade, catalog color

**Color catalog**:
A Brand's table of Bead colors (ADR 0072, ticket 536), its own entity: every Form factor of the Brand names it by `colorCatalog` (all Delica sizes share `miyuki-delica`, Miyuki Round has `miyuki-round`; TOHO numbers its colors in one series shared by every shape, so Cube and Round both name `toho`, and a code's sizes are those of each shape it exists in, `11/0` for a Round and `3mm` for a Cube, so each Bead sees its own subset, ticket 0694); a Form factor with none has no catalog and its Beads keep the default colors. Each code row holds the maker code, color family, shared Finish, the maker's finish wording and sizes (`domain/colorCatalog.ts`). The data is JSON in `src/data/colorCatalogs/`, made by `scripts/build-color-catalog.mjs` in the docs repo from Miyuki's public directory and by `scripts/build-toho-catalog.mjs` from a copy of the search data file of TOHO's old Japanese site kept in the docs repo (mixes and line beads left out, the Japanese finish tag kept beside our English wording; it has no Cube 1.5mm, no Round 10/0 or 7/0, no discontinued mark and only the Japanese retail range) merged with the text tables read from TOHO's international sample cards 111 (Round 11/0, 8/0), 110 (Round 15/0), 13 (Cube 1.5mm to 4mm) and PF (PermaFinish), kept in the docs repo with the card PDFs and their dates (ticket 0695): a code on a card is international and takes the card's sizes and its finish from the card's heading, a code on no card is left out of the catalog (ticket 0712), since the range bd-beads users buy is the international one (the research's open question, answered so; the Japanese file in the docs repo still holds the Japan-only codes if the range is ever needed). For a size a card covers the card decides which codes exist; for 9/0, 6/0 and 3/0, which no card covers, the Japanese file is all there is, and Round 10/0 and 7/0 list nothing. The Demi Round card is read too but waits for a Demi Round Form factor. A card table says `checked-by-human: no` until a human has checked its codes against the card image, and `toho.json` then names the unchecked cards in `uncheckedCards`; the five tables were checked on 2026-10-30 (the OCR-uncertain cells by eye, the rest by two OCR passes agreeing), so `toho.json` names none. Both scripts are run by hand, and the JSON is loaded by `services/colorCatalogs.ts` as one lazy chunk per catalog, validated on load; a file is found in the folder at build time and known by its name, so a new catalog is its file alone (ADR 0078), so it is never in the main bundle. Delica holds 1,919 codes (1,288 of 11/0). Miyuki Round holds 832 codes (611 of 11/0; ticket 0693), from the same directory in the same run: the key is Miyuki's seed-bead number with its letter suffix (`1F`, `401`), never the `#` or an old number in parentheses (`#477(409R)` is `477`), the 18 square-hole 6/0 codes say `Square hole (SH)` in their wording, 2/0 and 5/0 are kept as sizes though the registry has no Bead of them (every such code is also 6/0), a code none of whose listings names a color family (today code 596) is left out, and no Round code is flagged discontinued, as Miyuki publishes that list for Delica only. TOHO holds 1,066 codes (1,064 of 11/0): the codes of the four cards, classified by the full facts-only table of TOHO's file (678 Round and Cube codes; the repo owner said on 2026-10-29 it may be committed, closing ticket 0694's human box), whose 5 codes on no card are dropped (tickets 0695, 0712). Open to everyone, a Guest included. See ADR 0002.
_Avoid_: color library, swatch catalog

**Finish**:
The one shared list every Brand's own finish wording is mapped onto: transparent, opaque, ceylon, silver-lined, luster, matte, rainbow, metallic, plated (ticket 536). A code keeps the maker's wording beside it for display (Miyuki's "Opaque · Metallic" is metallic). Where Miyuki gives several tags, the first of plated, metallic, rainbow, matte, silver-lined, luster wins, else its glass type decides. TOHO's Japanese tags are mapped the same way, ours not TOHO's (ticket 0694): its platings (ニッケルメッキ, 仁丹メッキ, 本金メッキ, 銅メッキ, ＰＦ加工) are plated, 玉虫, 高級玉虫, ブロンズ and コゲ金 metallic, オーロラ rainbow, ツヤケシ matte, 銀メッキ and 中染 silver-lined, ラスター and サニー luster, セイロン, パール and シルク ceylon, else スキ is transparent and ギョク or a dyed code alone opaque; the wording keeps each tag, "Frosted (ツヤケシ)".

**Form factor**:
The shape of a family of Beads (e.g. round, Delica, cube), a lookup row that carries its outline and its number and direction of holes, so a new shape is data, not code (ADR 0072). Its name is a literal, the same in every language as the maker names it on the bag (Round, Cube, Delica), held once in the domain by its name key, so a new shape is its row and its name (ADR 0078, ticket 0692). In a Real Bead shape it decides the outline of a project cell.
_Avoid_: bead outline
**Brand**:
The maker of a Bead (TOHO, Miyuki), a lookup row with a literal name and, for a Brand with a set of its own, its color families (ADR 0078): they are the Project's built-in colors and the base of its Color catalog's generated swatches, and a Brand without them takes the twelve. Miyuki's 16 are the directory's families; TOHO's 21 are our English words for the hue tags of its Japanese search data, every tag that is some code's only hue (the twelve, Lime, Aqua, Navy, Beige, Gold, Silver, Copper, Crystal, Iridescent), named after TOHO's tags, not TOHO's official colors (ticket 0694). A layer's Bead copy saves the Brand's id and name only. Not the app's Wordmark.
_Avoid_: manufacturer, make
**Bead size**:
A Bead's size as its maker states it (11/0, 1.5mm), a literal. It is part of the Bead's id and says nothing by itself about the footprint: 11/0 is 1.6mm for Delica, 2.0mm for Miyuki Round and 2.2mm for TOHO Round.
_Avoid_: bead number, gauge

**Bead shape**: how a layer's cells are drawn, no longer a setting (ticket 0724, superseding ADR 0068's Symmetric or Real choice): every cell is drawn as Real was, with the Bead's real proportions (width along the thread, height across it) and an outline from its Form factor, a rounded rectangle, so a Delica reads as a cylinder seen from the side and a Round as a pill. Each layer draws with its own Bead, in the Canvas, Starters, image conversion, exports and print alike. A `beadShape` an older file saved, of either value, is read and ignored, and nothing writes one. Grid positions, sizes counted in beads and Beads needed do not depend on it.
_Avoid_: cell shape

**Drop** (N-drop; was Brick block, ticket 477): how many beads each stitch picks up, as weavers say "2-drop peyote" or "3-drop brick stitch", 1 to 20, default 1 (ordinary peyote or brick stitch). Drawn as rows in blocks: N rows straight beside each other, then N shifted half a bead, and so on, so the shift repeats every 2N rows and a Frame's top edge resizes by a multiple of 2N rows. Only which rows shift changes: rows sit as far apart as at 1, and peyote's still nest. Peyote and brick stitch each have their own Drop, a stepper beside the Technique choice in Layer settings and the new-project form, shown only for its own Technique and kept if the Technique is switched away and back; loom has none. Row progress's passes and the Word chart don't change with it. A setting of each layer saved with the file (older files read as 1, and an older file's Brick block as brick stitch's Drop); changing it on an open Project is one Undo step that keeps every bead's row and column, and the Frame's waits while Row progress is on. Its hover text says what it does.
_Avoid_: Brick block, Peyote block

**Technique**:
The weaving method used (loom, peyote, brick stitch), which determines the grid geometry/offset of a layer's cells. A Project has a **Canvas Technique** and a **Frame Technique** (ticket 492, ADR 0038): each layer is woven in its own, a peyote Frame on a loom Canvas or the other way round, and each layer has its own Bead too. Each is chosen when its layer is made: a new layer copies the layer it is made from or with, or a Starter's: a new Project's Canvas takes the Technique the form chose and its Frame the same; a Frame made later from a Selection or Fit to drawing takes the Canvas's. Each is changed on its own in its layer's Layer settings (ADR 0079, ticket 0670): the Canvas's in the Project panel's Canvas section, any time, the Frame's in the Frame panel; the one Technique control that changed the Frame's when the Project had one, else the Canvas's (tickets 351, 554), is gone. Only the geometry changes (row shift and row pitch), so the layer keeps its columns, rows, Bead and place and every cell keeps its row and column (a picture drawn for one technique will look different in another). One undo step; on a Frame it waits while a Row progress pass is done. A layer's own first row is always an unshifted one, so nothing needs to start on an even row once a Frame exists. All three switch among each other (ticket 0502, ADR 0038): every Technique has a position at every row and column, so no bead is dropped and nothing is asked. Each Technique's entry names its **geometry kind** with that kind's values (ADR 0078, ticket 0621): **rows** (loom, peyote and brick stitch: shift, row pitch, cell, roundness, passes). The layout and Row progress's passes come from that kind's geometry, never from the Technique's name, so a Technique on an existing geometry is one entry.
_Avoid_: stitch, weave type

**Weave**:
A Technique together with its settings (peyote's and brick stitch's Drop): what a layer is woven in. The Canvas and the Frame each have one, and changing any part of it is one Undo step that Undo restores whole.
_Avoid_: Technique (when the settings are meant too), technique settings
