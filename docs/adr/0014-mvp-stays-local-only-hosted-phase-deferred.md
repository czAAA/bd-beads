# SaaS release stays local-only at MVP; hosted accounts are a later, deliberately deferred phase

bd-beads is becoming a paid product, which raises the question ADR 0001 left open ("cross-device sync can be added later if the need arises"): when does "later" arrive? This MVP release keeps ADR 0001 unchanged — still local-only, no accounts, no server — and adds only client-side work: richer export (PDF/PNG/QR, see ADR 0015), a real design system, responsive layout from phone/tablet up to 24–34" displays, offline/installable support, and a landing page with a guided first-pattern tour. No accounts means no billing, no analytics, and none of the data-protection obligations that come with holding personal data, because none of it applies yet.

A second phase — hosted "paired accounts" (linking one person's own devices to sync their Pattern library, not sharing between different people) plus billing — is scoped out of MVP on purpose and tracked as blocked work, not started until after MVP ships. When it starts, the app server is self-hosted (a Raspberry Pi to start, chosen to avoid hosting cost while demand is still unproven), but the database is a managed free-tier service (e.g. Supabase, Turso, or Neon) rather than SQLite on the Pi itself, so a home power or internet outage can't take a paying customer's data down with it. The free tier stays fully-featured through an MVP promo period; specific features — starting with the unlimited-size hosted-link sharing from ADR 0015 — move behind a paid plan once usage data shows what's worth paying for.

**Considered options**: building accounts and a backend as part of MVP itself (rejected — deliberately deferred to validate the product's core editing/export experience first, without backend cost or complexity); hosting the database on the Pi alongside the app server (rejected — ties a customer's data availability to one home network and power supply).
