# The clipboard survives a Pattern switch, a tool switch, and cancelling — only a new Copy or Selection clears it

> Since [ADR 0028](0028-a-canvas-is-a-project-a-pattern-is-what-the-frame-holds.md) the saved thing is called a Project; "Pattern" below means that, and the text keeps its original words.

Undo/Redo history and the Selection both reset on a Pattern switch (see CONTEXT.md's Undo and Selection entries), and until ticket 92 the clipboard (CONTEXT.md's Copy) followed the same rule, plus its own extra ones: leaving the Select tool or cancelling out of Paste (Escape/right-click) also dropped it. Ticket 92 (`?` keyboard paste, Ctrl/Cmd+V) breaks the clipboard away from that shared rule on purpose: it now clears only when a new Copy replaces it or a new Selection is made, and survives a Pattern switch, a tool switch, and a cancel.

The reason is what Ctrl/Cmd+V is for. It pastes at the cell under the pointer from whichever tool is active — Paint, Fill, Select or Erase — precisely so a copied motif can be carried into a different editing context without re-copying it. If leaving Select still dropped the clipboard, Ctrl/Cmd+V could never actually be used from Paint/Fill/Erase: the moment you switched tools to use it, there would be nothing left to paste. The same argument extends to a Pattern switch — copying a motif in one Pattern and pasting it into another is exactly the kind of thing a keyboard shortcut should make easy, not something the tool-switch or Pattern-switch reset should quietly forbid.

Undo/Redo and Selection don't get this same exemption because they're tied to a specific grid's history or a specific rectangle of it; neither means anything once the grid underneath has changed. A copied block is just colors, portable to any grid of any size (pastedCells already clips silently past an edge), so nothing about a Pattern switch invalidates it.

Cancelling (Escape/right-click) and leaving Select no longer drop the clipboard either, but they still have to stop the *visible* paste projection — the live preview and the click-to-stamp gesture are Select-tool-only affordances, and a stray click under Paint/Fill/Erase must never accidentally stamp. Both instead set a "dismissed" flag (see `pasteDismissed` in App.vue): the projection stays hidden, and switching back to Select alone does not revive it — only a new Copy or a new Selection does. Ctrl/Cmd+V ignores the flag entirely and keeps pasting the same clipboard regardless, since it was never the visible-projection gesture the flag exists to gate.

**Considered options**: re-arming the projection automatically on returning to Select (rejected — a paste projection reappearing without the user having done anything new reads as the editor stamping something on its own, and the two real re-arm triggers, a new Copy or a new Selection, are exactly the actions that would naturally leave something worth previewing); keeping the old "any tool switch or cancel drops the clipboard" rule and giving Ctrl/Cmd+V its own separate, Select-only clipboard (rejected — two clipboards for one Copy gesture is confusing to build and worse to explain, and it would mean Copy-while-not-Select doesn't exist, which the ticket doesn't ask for).
