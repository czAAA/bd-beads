# Editing tools live above the canvas, not in the left main panel

_Superseded in layout by [ADR 0021](0021-visual-language-follows-design-md.md), built in ticket 141: the Toolbox is the first box of the left column and scrolls with it; it no longer sticks (the ticket 114 amendment's `position: sticky` rail and the 2026-09-18 sticky panel are gone), and the page no longer scrolls. Ticket 144 then moved the Progress bar to the canvas box's bottom edge, always shown, and removed the Row progress group: the 2026-09-22 amendment's placement by Pattern shape, and the Enabled and Direction toggles in the Toolbox, are gone._

_Amended by [ADR 0021](0021-visual-language-follows-design-md.md): the Toolbox becomes the first box of a 312px left column that scrolls on its own. It keeps Tools (as tabs), Colors and Edit, with Mirror and Size as disclosure rows. Save and Export move out to the save box below it. The Row progress group is removed: its Enabled toggle becomes a switch at the start of the Progress bar, and Direction becomes the bar's Turn row direction button. The Progress bar always runs along the canvas box's bottom edge, no longer placed by Pattern shape. The design system's component cards have the details._

_Amended by ticket 40: the second row is the **Toolbox** (CONTEXT.md), reorganized into five titled **Tool groups** — Tools, Colors, Edit, Mirror, Row progress — each laying its controls out left to right in a two-row grid (at most seven per row). "Strip of small cards" below is superseded by this; avoid "card"/"tool strip" wording going forward._

_Amended by ticket 35: the "New Pattern" / zoom-controls row the Toolbox used to sit below is gone — New Pattern moved into the top bar (see [ADR 0004](0004-three-panel-app-shell.md)'s amendment) and zoom became a floating stack on the canvas box's own right edge, reversing ticket 18's choice to keep zoom off the box while keeping the rest of ticket 18 (the box's snug fit to the Pattern and its border on all four sides). The Toolbox is now the above-canvas panel's first and only content, not a second row below one._

_Amended by ticket 51: zoom moves again, from the floating right-edge stack to a compact cluster fixed to the canvas box's top-right corner (see [ADR 0004](0004-three-panel-app-shell.md)'s amendment). The Toolbox remains the above-canvas panel's only content either way._

_Amended by ticket 57: corrects ticket 51 — the cluster is fixed to the **canvas panel's** top-right corner (`App.vue`), not the Pattern's own sized box nested inside it (`PatternCanvas.vue`); see [ADR 0004](0004-three-panel-app-shell.md)'s amendment._

_Amended (2026-09-18): the above-canvas panel is now `position: sticky` (`.app-shell__above-canvas`), pinned near the top of the viewport once scrolled to. A tall Pattern grows the canvas panel past the viewport's height (vertical overflow is never trapped inside the shell — the page itself scrolls, per `.app-shell__canvas`'s own comment), so without this the Toolbox would scroll out of view while working on a Pattern's lower rows. Its containing block is a new wrapper around just the above-canvas and canvas panels (`.app-shell__canvas-column`), not the whole right-hand column, so it un-pins once the canvas has scrolled past rather than staying stuck over the below-canvas section (Beads needed/Saved Patterns/Export) too._

_Amended by ticket 98 ([ADR 0017](0017-grid-is-the-size-mm-is-an-estimate.md)): the Toolbox gains a sixth **Tool group**, **Size**, between Mirror and Row progress. It shows the open Pattern's Estimated size with a warning tooltip and holds the columns and rows inputs that Resize uses (tickets 101 and 102). It follows the same rules as the other groups: one titled box, sized to its content, collapsing on Escape._

_Amended by ticket 114: **the Toolbox is no longer above the canvas.** It is a fixed-width rail down the left of the app shell, in the column that also holds the New Pattern form (the form shows with no Pattern open or during a Convert image framing step, the rail otherwise), and the canvas panel takes the full width beside it. Tool groups stack vertically. The rail is 200px wide on a large display and 172px on a tablet (`max-width: 1100px` or a coarse pointer), with controls in four 36px columns, or three 44px ones on a tablet so a finger has a full-size target. It is still `position: sticky` (`top: 24px`), but its containing block is now the left column's cell in the same grid row as the canvas panel, so it un-pins when the canvas has scrolled past; it is capped at the viewport's height and scrolls within itself when its groups add up to more than a short window shows. **The cap-and-expand rule is re-decided**: a group shows at most 16 controls (four rows of four) instead of 14 (two rows of seven). No group reaches that today (Colors has 13): hover-expansion is no way to reach the Palette on a touch screen, and the rail has room to grow downward. The expand-in-place behaviour, and Escape collapsing an expanded group before anything else, remain as a safety net for a future group rather than something current groups rely on. Mirror's counters put their value on a line above their two buttons, and Size's rows wrap inside the rail. Ticket 79 keeps the rest of the responsive work (phone, and the shell as a whole). "The strip above the canvas" and the two-rows-of-seven grid in the ticket 40 note above are superseded._

_Amended (2026-09-22): the Row progress group's moment-to-moment controls — the current-row readout and the Previous/Next buttons that move it — leave the Toolbox for **Progress bar** (CONTEXT.md), a new control attached to the canvas panel itself. The Enabled and Direction toggles stay put, leaving the Toolbox's Row progress group with two controls instead of five. This follows the same move ticket 35 already made for zoom (out of the above-canvas/Toolbox area, into the canvas panel), not a new kind of relocation. Progress bar's position follows **Pattern shape** (CONTEXT.md — rendered width vs. height, independent of Rotate and Row direction): a vertical Pattern gets it as its own column on the canvas panel's right edge, next to the grid; a horizontal Pattern gets it as its own row, stacked below — deliberately not merged with — the zoom cluster's row, so the two stay legible as separate concerns. Both placements are `position: sticky`, so Progress bar stays reachable while scrolling a tall Pattern regardless of which shape bucket it falls in; this is the first canvas-attached control to use `sticky` outside the Toolbox rail itself. (Zoom, by contrast, is an ordinary in-flow block that scrolls away with the page — the "fixed to the panel" wording in the ticket 51/57 amendments above describes its intent, not its shipped CSS, which uses `margin: 0 0 12px auto` inside normal block flow.) Progress bar reserves no space and renders nothing while Row progress is off, matching the Row progress marker's own existing show-only-when-enabled behavior._

[ADR 0004](0004-three-panel-app-shell.md) assigned painting/fill/mirror tools to the left main panel. Moved instead to the above-canvas panel, as a second row below the existing "New Pattern" / zoom-controls row: the tool picker, palette, undo, mirror controls, and row progress now all render there, styled as a strip of small cards on a dot-grid notepad-paper background. This keeps the editing tools next to what they act on (useful for the mirror axis line and hover preview, which relate directly to the grid) and gives them the horizontal room the redesigned mirror controls (two axis toggles plus two "mirror current" buttons) need.

The left main panel keeps its original New Pattern form role, but while a Pattern is open it now renders nothing. This is not the ADR 0004 "coming soon" placeholder — that convention is for a panel whose feature hasn't been built yet, whereas this panel's content moved elsewhere on purpose — so it collapses instead, and the canvas area reclaims the freed width.

**Considered options**: keeping tools in the left panel (rejected — too cramped once the mirror redesign added two more buttons, and it kept the tools visually separate from the canvas they draw on).
