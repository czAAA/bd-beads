# Convert image creates a Pattern at a fixed physical size

Ticket 58 lets a new Pattern be created from a picture rather than from an empty grid. A picture brings its own proportions, and a Pattern's grid is derived from its real-world size divided by its Bead's footprint (ticket 01), so the two will rarely agree. The Pattern's real-world size stays authoritative: the user states width and height as for any other new Pattern, and the picture is scaled and cropped to fit that frame — not the reverse, where the picture's proportions would set the Pattern's dimensions. This is the same principle [ADR 0008](0008-replace-bead-recalculates-grid.md) applies to Replace Bead, for the same reason: the finished piece is being made at a specific real-world size, and where its picture came from does not change that.

Because the frame is fixed and the picture is not, the framing step is where the mismatch gets resolved. The picture is zoomed and panned beneath a frame whose proportions follow the Pattern's physical size — physical size, not cell count, so a non-square Bead footprint such as Delica's 1.6 × 1.3mm cannot distort it. Zoom is clamped so the picture always covers the frame, meaning a converted Pattern can never be created with unfilled bands down its sides; an empty cell is a cell with no bead in it, which would read as a deliberate hole rather than as an artifact of fitting a picture. Sampling takes each cell's true centre from the Technique's own grid geometry, so peyote's half-cell stagger and tighter row packing and brick stitch's stagger are reproduced rather than flattened into a plain rectangle.

Conversion is a creation option only, never a drawing command on an open Pattern. As a drawing command it would have to answer to the Row progress lock, to Mirror's strips the way Paste does, and to the undo stack — four glossary questions with defensible opposite answers, settled for a feature whose value is still unproven. Adding it later costs nothing that is decided here.

**Considered options**: deriving the Pattern's height from a stated width and the picture's aspect ratio (rejected — it removes cropping and the frame UI entirely, but makes it impossible to convert a picture into a Pattern of a size the maker actually wants, such as a 4 × 18cm bracelet); stretching the picture to fill a mismatched frame (rejected — distorts the artwork silently, and flat artwork is exactly where distortion is most visible); allowing zoom below cover so that unfilled frame area becomes empty cells (rejected for now — a deliberate silhouette is a plausible want, but it is indistinguishable from the accident of having zoomed out too far, and a picture with a transparent background already provides the deliberate path to a silhouette).
