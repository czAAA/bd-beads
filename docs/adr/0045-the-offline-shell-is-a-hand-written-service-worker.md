# The offline shell is a hand-written service worker that updates when the person asks

**Status: accepted.** Ticket 69, spec 382. Builds on [ADR 0001](0001-local-only-persistence.md) and [ADR 0014](0014-mvp-stays-local-only-hosted-phase-deferred.md).

Every Project lives on the device, so the app must open with no internet and while our hosting is down; otherwise a refresh puts the browser's error page between the artist and their own work. A service worker keeps the last version of the app on the device and a manifest lets it be installed.

- **Hand-written, no library.** The worker is `pwa/serviceWorker.js`, about eighty lines, copied into the build as `sw.js` by `vite.pwa.ts`, which fills in the list of every built file (public files, fonts and lazy chunks included) and names the cache after their content. A build that changes anything is a new cache, so an old version never serves half of a new one. No new dependency, and the worker is the only code that has to be read to know what it does.
- **Pages are network-first, everything else cache-first.** `index.html` and the Overview ([ADR 0040](0040-the-overview-is-a-second-page.md)) go to the network and fall back to the copy on the device when there is none, when it is slower than four seconds, or when the host answers with anything but success (an outage often shows as a 503). Hashed files, fonts and icons come from the cache. The worker does not store what the network returns: a new `index.html` seen by an old worker would point at files its cache does not have. Anything outside the build, such as the API, goes to the network as if there were no worker.
- **No automatic `skipWaiting`.** A new version installs in the background and waits. The open page shows "Update ready" with a Reload button that stays until answered; Reload tells the waiting worker to take over and reloads that tab only. Otherwise the version arrives when every tab of the old one has been closed, which is the next time the installed app is opened. A tab is never reloaded under the person, and an old and a new tab can be open together, so saved-data migrations stay forward-compatible for one version. Plain reloads of the page keep the old worker, because the page is still its client; that is what Reload is for.
- **Silent.** The worker is registered after the page has loaded, and nothing is said about the download. The very first visit needs the network once. Before the code arrives, `index.html` carries an inline splash of the three loading beads (Loading card), shown only after the 300 ms loading delay and removed when the app mounts; with `index.html` kept under 14 KB, the first round trip.
- **Installable, nothing more.** A manifest (`display: standalone`, icons and colours from the design system) and `navigator.storage.persist()` so the browser does not clear the library under storage pressure. No push, background sync or install button.

**Known edges**: a page fetched from the network by an old worker is the newer version's, whose files the old cache does not hold; online they come from the network, and if the connection then drops, the next reload falls back to the old version's complete copy. A tab left on the old version can ask for a chunk the new host no longer has once the new version has taken over; reloading it fixes that. The four-second wait before the copy answers is a choice, not a requirement: on a connection that stalls the person gets the app from the device rather than a blank tab.

**Considered options**: Workbox through `vite-plugin-pwa` (rejected: a dependency tree for what is a file list and three strategies, and one more thing to keep working with Vite's releases); `skipWaiting` with an automatic reload (rejected: it takes the canvas away mid-stroke and runs new code against pages that were loaded with the old); caching what the network returns for pages (rejected: see above); serving a branded "you are offline" page (rejected: the app itself opens, which is the point).
