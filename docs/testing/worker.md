# The Worker's tests

Part of the testing docs; the rules every test follows are in [`docs/testing.md`](../testing.md).

`worker/test/*.test.ts` (ticket 71) are their own Vitest project (`worker`, in `vite.config.ts`), run in Node by the same `vitest run`. They start the real Worker in workerd through Miniflare 4, configured from the repo's own `wrangler.jsonc` for dev or production, plus made-up limits and warn levels (`TEST_LEVELS`; the real ones are dashboard variables, not in the file; a test passes `undefined` in `vars` to leave one unset) (`worker/test/harness.ts`), with local D1 and R2, and drive it black-box over HTTP and its `scheduled()` entry. Outbound calls (Turnstile, GraphQL Analytics, Healthchecks.io, GitHub) are caught by the harness and answered by the test. `worker/test/fixtureWorker.ts` is the deployed Worker plus routes and a daily hook that exist only for the tests (the guards and blob stores have no caller until the feature tickets); never deployed. Until ticket 0078 gives them a caller, `knip --production` takes the guards, body reader, blob stores and the fixture Worker as entries of their own (`knip.jsonc`), so they are not reported as test-only; 0078 removes that.

- **Seam 1** (`api.test.ts`): requests in, responses out: health, an unknown path, a path parameter that can't be decoded, kill switches, the Origin check, Turnstile with Cloudflare's dummy keys and the hostname a token was made on, size caps, the blob storage limit, rate limits through Miniflare's own Rate Limiting binding, both blob stores, no CORS, static assets. `access.test.ts` (ticket 0395) drives dev's Access check the same way, with tokens signed by a key the test makes and the team's certs answered through `reply`; it starts the harness with `access: true` (every other test runs without the check) and asks each dev hostname by full URL. A route's own file beside it (`feedback.test.ts`, ticket 0699) drives that route the same way, with `wrangler.jsonc`'s own `ratelimits` (the harness declares them) and the Worker's console lines in `logs`.
- The fake verifier answers with the Worker's own hostname (ticket 1024: a token counts only for the host it was made on). Cloudflare's real one answers `example.com` for its dummy keys (asked 2026-11-16), so a Worker run by hand with a dummy secret refuses every token.
- **Seam 2** (`watchdog.test.ts`): the Cron Trigger's run: success and `/fail` pings, dev's and production's levels, what each counts, a reader that fails, the daily hook.
- A change to `worker/migrations/` needs no extra test: the harness applies them before each Worker starts, so a broken one fails everything.
- Why Miniflare directly: `@cloudflare/vitest-pool-workers` supports Vitest 4 only, and Wrangler pins a Miniflare 5 alpha. Miniflare 4's workerd accepts compatibility dates up to 2026-08-06, which bounds `compatibility_date` in `wrangler.jsonc` until Miniflare is upgraded with it. Its last release, `4.20260730.0`, pins `undici` and `sharp` to versions with advisories, so `overrides` in `package.json` raises them to the patched releases Wrangler's own Miniflare uses. Drop the overrides when Miniflare goes to 5, and refuse Dependabot's move to a Miniflare 5 alpha. Miniflare's `dispatchFetch` sends a buffered body in chunks unless the test sets `Content-Length`, as a browser always does.
