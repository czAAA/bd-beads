# App shell layout

Where everything sits on the screen. Moved out of `CONTEXT.md`'s Key concepts (ticket 358), which keeps a one-line entry. The tiers and their measurements are in the design system's [`responsive.md`](design/system/responsive.md); this file says how the app arranges them.

## The Tool pill layout (every width)

**The whole screen is one layout at every width** (ADR 0046; ticket 412, and ticket 439, which replaced its Dock with the Tool pill), in portrait and landscape: no header, no left column. The canvas box is the screen, flush with every screen edge (the safe-area inset where larger; ticket 0513), and nothing sits below it. The tools float as the **Tool pill** over the drawing area: grip, the six tool tiles, a divider, the colour control and, where the device needs it, a second divider and Pen/Mouse; 48px across, `pill-gap` (6px) in from the edge it is docked to, centred along it. It docks left, top, right or bottom (default bottom), is dragged or moved with its grip, or set in the Menu panel's Tools position, and is remembered on the device; it scrolls along its length when longer than its edge, and it sits outside the canvas's zoom, so it never zooms. The drawing runs behind it: Fit to drawing, the initial fit and the pan limits reserve nothing for it, and the Selection bar keeps clear of its rectangle. Its colour control opens the colour popover (no Colour sheet on any device); the panels hold what the header and column held. With no Project open, the New Project / Import bar takes the Progress bar's place and there is no pill. Menu, Project and Frame are the Canvas strip's first buttons (tickets 431, 555), and each opens its panel as a dropdown under it on every device (ADR 0046).

The shell is a notice row (only while there is something library-wide to say), then the canvas box, which takes all the width and the remaining height, flush with every edge (the safe-area inset where larger). The page itself never scrolls; the Project scrolls inside the canvas box (ADR 0026), and the Progress bar (or the New Project / Import bar) is the canvas box's footer. There is no standalone Select all button: it is the Selection bar's first item and Ctrl/⌘+A, so a touch-only user must first drag a Selection (a Menu entry can be a later ticket).

Read ADR 0021 before adding a new screen or control.

In this layout the Canvas strip stays, one slim row at every width, and owns the canvas controls (tickets 425, 543, ADR 0046): Menu, Project and Frame on the left (icon + text; Project and Frame with a Project open), the Brand in the middle (the logo and the openbeads wordmark, opening the Overview), then Rotate canvas, Rulers (R), Undo, Redo, zoom out, zoom in and Fit on the right. It has no title, size line, printed-size estimate, grid icon or keyboard hint, and there is no Zoom pill. Under 1024px the words and the wordmark go and only icons stay; on an editor phone there is no Brand. The Canvas color is picked in the Project panel's Canvas section. While a picture is being framed (Convert image) the strip holds Menu and the framing step's own zoom.
